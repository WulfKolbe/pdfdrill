# 010 — Reference stub at first citation

## Status: implemented, tested, and the penev_A target met after three fix rounds.

Round 0 put stub-creation solely in `CitationProcessor.process_objects`, a
model-build-time post-pass — correct in isolation, but penev_A showed most of
its Citations are created LATER, by `pdfdrill/bibliography.py`, so only 1 of
52 keys got a stub. Reported as NEEDS_CONTEXT rather than guessed at. The
coordinator's ruling (fix round 1): the spec's own words — "Create an empty
Reference on first Citation" — apply wherever a Citation is created, so
stub-creation moved into ONE helper called by every Citation creator.
penev_A then measured 52 References / 52 distinct keys, all stubs — but 162
`cites` Alignments for 81 Citations, because the same edge got added twice
(once by the new helper at creation time, once by `cmd_bibliography`'s
unconditional relink pass). Fix round 2: made edge-creation idempotent
through one shared helper; penev_A then measured exactly 81 `cites`
Alignments for 81 Citations — but re-running `cmd_bibliography --force` a
SECOND time duplicated Citations (81 → 106), because its cleanup step
decided "did bibliography already run" by whether a non-stub Reference
existed, and 010's own stubs made that always-false once a document had
gone through this fix. Fix round 3 (this round): the cleanup gate now
decides by provenance (`added_by`) instead, regardless of whether every
Reference is a stub; penev_A now measures 81/52/52/81, twice in a row.

## WHAT CHANGED

- `src/docmodel/modules/citation.py` — new module-level
  `ensure_reference_stub(doc, citation: DocObject, bibkey: str) -> Optional[DocObject]`.
  Returns the existing Reference for `citation`'s citekey (a stub from an
  earlier citation with the same key, or one already filled by
  bibliography/bibsource/bibfetch) if there is one; otherwise creates a new
  stub (`props`: `citekey`, `bibkey`, `stub: True`, `ref_source: "citation"`)
  anchored at THIS citation's own surface Realization (same stream, same
  start/end anchor — reused, not a new one). Either way, links `citation` to
  the Reference via a `cites` Alignment (`props`: `citekey`, and `number`
  when the citation carries one — the same edge shape
  `bibliography.link_citations` produces, needed so an existing test
  asserting every `cites` edge carries a `number` didn't regress). No-ops
  (returns `None`) when the citation has no citekey or no surface
  Realization. Lives in `docmodel` (not `pdfdrill`) so `pdfdrill/
  bibliography.py` can import it with no cycle.

  Four call sites now call it, each right after `doc.add(obj)` /
  building the Citation, so "first occurrence" falls out of creation order
  with no separate pass and no population any one caller can't see:
  1. `CitationProcessor.create_object` (`src/docmodel/modules/citation.py`,
     `[key]`-bracket citations) — bumps `reference_stubs_created` only when
     no Reference existed for the key a moment before (counter semantics
     unchanged from round 0).
  2. `detect_numeric_citations` (`src/pdfdrill/bibliography.py` ~line 271,
     `[N]`/`[N,M]`/`[N-M]`).
  3. `detect_author_year_citations` (~line 334, `(Author, Year)` over
     `mathpix_lines`).
  4. `detect_author_year_in_objects` (~line 401, the stream-agnostic
     `[Author, Year]`/`(Author, Year)` scan over prose objects, for
     markdown/source models with no `mathpix_lines`).

  Each of the three `bibliography.py` sites pulls `bibkey` from
  `doc.meta.get("bibkey") or ""` (they're plain functions, not module
  instances with `self.bibkey`) and imports `ensure_reference_stub` locally,
  matching the file's existing per-function local-import style.

- `src/pdfdrill/bibliography.py` (unchanged from round 0, still current):
  - New `drop_dangling_cites(doc)` — removes `cites` Alignments whose right
    side no longer resolves to a Reference in the document; one that still
    resolves (typically a stub) survives. Used everywhere the old code
    blanket-cleared `cites` edges, so a stub's link survives a `--force`
    rebuild or a gold ingest instead of being destroyed and only sometimes
    relinked.
  - `add_reference_objects` (parsed References section, `cmd_bibliography`) —
    looks up a stub by citekey first; if found, fills its props in place
    (drops `stub`, sets `ref_source: "text"`) and keeps its id/anchor;
    otherwise creates as before.
  - `ingest_bbl` (author's `.bbl`, `cmd_bibsource`) — same fill-in-place
    pattern; `ref_source` set to the `source` arg (`"bbl"`/`"bibitem"`).
  - `load_bibtex_file` (`.bib`, `cmd_bibsource` and the `restrict`-ed path,
    ~line 486) — already merged fields onto any pre-existing Reference by
    key; added the one-line stub-clearing step (`pop("stub")`,
    `ref_source: "bib"`) when the matched Reference was a stub.
  - `build_bibliography_from_source` docstring: "no References exist yet" →
    "no *non-stub* References exist yet".

- `src/pdfdrill/commands.py` (unchanged from round 0):
  - `cmd_bibliography` — the "already ran" gate excludes stubs; the
    `--force` drop path only drops non-stub References and calls
    `drop_dangling_cites`.
  - `cmd_bibsource` — the "author's bibliography is authoritative, drop
    prior References" step keeps stubs and uses `drop_dangling_cites`.
  - `cmd_bibfetch` (API and keyless-delegate paths) — pops `stub` when an
    enrichment lands, so a bibfetch-filled stub reads as filled.

- `tests/test_reference_stub.py` — 5 tests (was 4):

  - The 4 round-0 tests unchanged in intent: 3-line fixture (`[a]`, `[b]`,

  - New: `test_bibsource_bib_fill_updates_stub_in_place` — calls
    `bibliography.load_bibtex_file` (the ~line-486 `.bib` creator

- `src/docmodel/modules/citation.py` (fix round 2) — new module-level
  `add_cites_alignment(doc, left: Range, right: Range, props: dict) -> Optional[Alignment]`,
  the one place a `cites` Alignment gets added. Skips (returns `None`) when
  an identical one — same `left`, same `right`, **and same `props["citekey"]`**
  — already exists; otherwise creates it and returns it.
  `ensure_reference_stub` now calls this instead of `doc.add_alignment`
  directly, and so does `bibliography.link_citations` (imported locally,
  same style as the other three call sites). `link_citations`'s docstring
  now says it's idempotent and that its return value is edges ADDED, not
  the total linked count.

  `citekey` had to be part of the identity check, not just `left`+`right`:
  a citation is anchored at LINE granularity (`start == end == the line`,
  sub-position is an `offset`/`length` prop, not part of the Range), so two
  DIFFERENT, never-seen-before citekeys parsed off the SAME line (e.g.
  `(Oja, 1989; Sanger, 1989; Plumbey, 1991)`) share one `left` Range — and
  each gets its own brand-new stub anchored at THAT line, so their `right`
  Ranges collide too. A first cut that deduped on `(left, right)` alone
  silently dropped one of every such pair as "already linked" when it was a
  genuinely distinct edge to a genuinely distinct Reference — caught by the
  penev_A measurement (71 edges for 81 Citations, 10 short) before it was
  caught by a test; `citekey` in the identity tuple fixed both.

- `tests/test_bibliography.py::test_numeric_citation_detection_and_linking`
  and `test_author_year_citation_detection_and_linking`, and
  `tests/test_bibsource.py::test_detect_author_year_in_objects_square_brackets_and_folding`
  — updated. All three pre-dated 010 and asserted `link_citations(doc) == N`
  meaning "N NEW edges added"; now that `detect_*` already links via
  `ensure_reference_stub` before `link_citations` ever runs, the correct,
  idempotent answer is 0 new edges (already linked), not N. The
  `test_bibsource.py` one also surfaced a genuine, separate, unfixed gap
  (see OPEN): `ensure_reference_stub`'s exact-citekey match can pre-empt
  `link_citations`'s fuzzy surname+year prefix match, so an abbreviated
  citekey (`"carlsson2009"`) that would have fuzzy-matched a fuller gold key
  (`"carlsson2009topology"`) instead gets its own spare stub Reference; the
  test now asserts that actual (imperfect) shape rather than silently
  weakening to match it.

- `tests/test_reference_stub.py` (fix round 2) — 2 new tests (7 total):
  - `test_link_citations_is_idempotent_against_ensure_reference_stub` (the
    one the ruling asked for) — runs the fixture through `CitationProcessor`
    (which calls `ensure_reference_stub` per Citation) then
    `bibliography.link_citations`; asserts 4 `cites` Alignments both before
    and after (one per Citation), and that `link_citations` returns 0 newly
    added.
  - `test_two_new_keys_sharing_one_line_each_get_their_own_edge` — a
    regression test for the citekey-collision bug found while measuring
    penev_A (above): two brand-new citekeys on one line (`[d, e]`) each get
    their own edge, not one dropped as a false duplicate of the other.
    Verified it actually catches the bug: reverting `add_cites_alignment`'s
    identity check to `(left, right)` only (dropping `citekey`) fails this
    test with `0 == 1`; restoring the fix makes it pass again.

- `src/pdfdrill/commands.py` (fix round 3) — `cmd_bibliography`'s `--force`
  cleanup step now runs unconditionally on `--force` (no longer gated on
  `existing` — non-stub References — being non-empty) and retracts by
  provenance: every `Citation` or `Reference` with `props["added_by"] ==
  "bibliography"`, then `drop_dangling_cites`. The old gate decided "did
  this command already run" by "does a non-stub Reference exist", which
  010's own stubs made permanently false for a document whose References
  are all still stubs — a state true right after every `model` build, so
  the cleanup was skipped and a second `--force` piled a fresh detection
  pass on top of the untouched first one (81 → 106 Citations, measured).
  The `if existing and not force: return` early-return gate (a SEPARATE
  check, "already ran without --force, use the cache") is UNCHANGED — the
  ruling scoped this fix to `--force` idempotency specifically; the
  early-return gate has the same shape of bug for a non-force rerun and is
  flagged, not fixed, in OPEN.

- `src/docmodel/modules/citation.py` (fix round 3) — `ensure_reference_stub`
  now stamps a new stub's `added_by` from the CREATING CITATION:
  `citation.props.get("added_by") or "citation"`. A stub made for a
  `detect_*`-created citation (`added_by: "bibliography"`) inherits that
  marker, so the new cleanup above retracts the Citation and its stub
  TOGETHER. A stub made for a `CitationProcessor`-created citation (which
  carries no `added_by` of its own) gets the literal marker `"citation"` —
  never matches `"bibliography"`, so it and its Citation both survive a
  `cmd_bibliography --force`, filled or not.

- `src/pdfdrill/bibliography.py` (fix round 3) — `add_reference_objects`'s
  FRESH-creation branch (no matching stub) now also stamps `added_by:
  "bibliography"` — this command made that Reference from nothing, so a
  `--force` rerun should retract and re-derive it exactly like a
  `detect_*`-created Citation. The FILL branch (an existing stub found)
  deliberately does NOT touch `added_by` — a `CitationProcessor` stub this
  fills must keep reading "citation", not start reading "bibliography", or
  it would get wrongly retracted (and its Citation left without a
  Reference) on the very next `--force`.

- `tests/test_reference_stub.py` (fix round 3) —
  `test_cmd_bibliography_force_is_idempotent_on_an_all_stub_document`: builds
  a Document (via `model_io.save_model` + a throwaway PDF, the same harness
  `test_bibsource.py::test_cmd_bibliography_falls_back_to_source_bib`
  already uses) with a REPEATED author-year citation on a separate line
  (`(Asai, 2023)` on two different lines, `(Wu, 2024)` on a third), calls
  `commands.cmd_bibliography(pdf, force=True)` twice, and asserts the
  (Citation, Reference, `cites`-Alignment) triple is identical after both
  calls. The repeat-on-a-separate-line shape matters: a fixture with only
  distinct, single-occurrence citekeys would pass even with the bug still
  present, because `ensure_reference_stub` anchors each stub at its OWN
  citation's line, so `cmd_bibliography`'s `ref_anchors` exclusion (skip
  re-scanning a Reference's own line) already happens to exclude every
  FIRST-occurrence line on a rerun regardless of whether cleanup is fixed —
  only a SECOND occurrence of an already-stubbed key, sitting on a
  different, non-excluded line, is free to re-detect and duplicate.
  Verified it actually catches the bug: reverting the `commands.py` gate to
  the old `if force and existing:` form fails this test with `(4, 2, 3) !=
  (3, 2, 3)`; restoring the fix makes it pass again.

No prop-contract change was needed: `stub` isn't in the committed
`corpus_props.json` snapshot (a walk of the library, last done for task 290,
not re-run here) so `table_violations()` doesn't see it yet; `ref_source:
"citation"` is a new value of an already-documented prop, not a new prop;
`added_by` is an existing, widely-used generic provenance prop (Equation,
Section, ...) and `"bibliography"` was already one of its values (on
Citations) before this round.

- ~~`cites` Alignments accumulate duplicates...~~ **Fixed this round** (see
  WHAT CHANGED — `add_cites_alignment`, shared by `ensure_reference_stub` and
  `link_citations`). penev_A now measures 81 edges for 81 Citations.
- ~~`cmd_bibliography --force`'s cleanup step only runs when `existing` --
  non-stub References -- is non-empty...~~ **Fixed this round** (see WHAT
  CHANGED — the cleanup gate now decides by `added_by` provenance,

- **New, separate finding from measuring THIS fix (not a defect in the fix
  itself — a one-time upgrade caveat, not fixed, not asked for):** the new
  cleanup can't retroactively clean up a Reference created by
  PRE-round-3 code. Restoring penev_A's round-2 snapshot
  (`model.after_bibliography_v2.json`, built before `ensure_reference_stub`
  started stamping `added_by` on a stub) and running `bibliography --force`
  twice lands on a STABLE but wrong 26 Citations / 17 keys / 52 References /
  162 edges both times, not 81/52/52/81: those 52 stub References carry no
  `added_by` at all, so the new cleanup retracts their 80 orphaned Citations
  but not the stubs themselves, and the 52 survivors' anchors then exclude
  most of the document's citation-bearing lines from re-detection
  (`ref_anchors`). Any document that had `pdfdrill bibliography` run on it
  BEFORE this fix lands will hit this once, on its first post-upgrade

  `model --force`-only baseline runs clean at 81/52/52/81 twice — Scenario B
  in `run4_script.py`/`run4_result.json`, alongside the literal-ask Scenario
  A above). Fixing it would mean a migration pass or a different retraction
  strategy for objects with no `added_by` at all, which is a design
  decision, not this round's one item.
- **Also still open (same shape of bug, different call path, NOT fixed —
  the ruling scoped this round to `--force` specifically):** the
  `if existing and not force: return` early-return gate right above the
  fixed cleanup uses the SAME "does a non-stub Reference exist" test to
  decide "did bibliography already run, use the cache" on a bare (non
  `--force`) call. A document whose first `cmd_bibliography` run created
  only stubs (true whenever the heuristic text parse finds 0 entries, as on
