# 010 — Reference stub at first citation

## Status: implemented, tested, and the penev_A target met after a fix round.

Round 0 put stub-creation solely in `CitationProcessor.process_objects`, a
model-build-time post-pass — correct in isolation, but penev_A showed most of
its Citations are created LATER, by `pdfdrill/bibliography.py`, so only 1 of
52 keys got a stub. Reported as NEEDS_CONTEXT rather than guessed at. The
coordinator's ruling (fix round 1): the spec's own words — "Create an empty
Reference on first Citation" — apply wherever a Citation is created, so
stub-creation moved into ONE helper called by every Citation creator. Fixed;
penev_A now measures 52 References / 52 distinct keys, all stubs.

## WHAT CHANGED

- `src/docmodel/modules/citation.py` — new module-level
  `ensure_reference_stub(doc, citation: DocObject, bibkey: str) -> Optional[DocObject]`.
  Returns the existing Reference for `citation`'s citekey (a stub from an
  earlier citation with the same key, or one already filled by
  bibliography/bibsource/bibfetch) if there is one; otherwise creates a new
  stub (`props`: `citekey`, `bibkey`, `stub: True`, `ref_source: "citation"`)
  anchored at THIS citation's own surface Realization (same stream, same
  start/end anchor — reused, not a new one). Either way, links `citation` to
  the Reference via a `cites` Alignment (`props`: `citekey`, and `number`
  when the citation carries one — the same edge shape
  `bibliography.link_citations` produces, needed so an existing test
  asserting every `cites` edge carries a `number` didn't regress). No-ops
  (returns `None`) when the citation has no citekey or no surface
  Realization. Lives in `docmodel` (not `pdfdrill`) so `pdfdrill/
  bibliography.py` can import it with no cycle.

  Four call sites now call it, each right after `doc.add(obj)` /
  building the Citation, so "first occurrence" falls out of creation order
  with no separate pass and no population any one caller can't see:
  1. `CitationProcessor.create_object` (`src/docmodel/modules/citation.py`,
     `[key]`-bracket citations) — bumps `reference_stubs_created` only when
     no Reference existed for the key a moment before (counter semantics
     unchanged from round 0).
  2. `detect_numeric_citations` (`src/pdfdrill/bibliography.py` ~line 271,
     `[N]`/`[N,M]`/`[N-M]`).
  3. `detect_author_year_citations` (~line 334, `(Author, Year)` over
     `mathpix_lines`).
  4. `detect_author_year_in_objects` (~line 401, the stream-agnostic
     `[Author, Year]`/`(Author, Year)` scan over prose objects, for
     markdown/source models with no `mathpix_lines`).

  Each of the three `bibliography.py` sites pulls `bibkey` from
  `doc.meta.get("bibkey") or ""` (they're plain functions, not module
  instances with `self.bibkey`) and imports `ensure_reference_stub` locally,
  matching the file's existing per-function local-import style.

- `src/pdfdrill/bibliography.py` (unchanged from round 0, still current):
  - New `drop_dangling_cites(doc)` — removes `cites` Alignments whose right
    side no longer resolves to a Reference in the document; one that still
    resolves (typically a stub) survives. Used everywhere the old code
    blanket-cleared `cites` edges, so a stub's link survives a `--force`
    rebuild or a gold ingest instead of being destroyed and only sometimes
    relinked.
  - `add_reference_objects` (parsed References section, `cmd_bibliography`) —
    looks up a stub by citekey first; if found, fills its props in place
    (drops `stub`, sets `ref_source: "text"`) and keeps its id/anchor;
    otherwise creates as before.
  - `ingest_bbl` (author's `.bbl`, `cmd_bibsource`) — same fill-in-place
    pattern; `ref_source` set to the `source` arg (`"bbl"`/`"bibitem"`).
  - `load_bibtex_file` (`.bib`, `cmd_bibsource` and the `restrict`-ed path,
    ~line 486) — already merged fields onto any pre-existing Reference by
    key; added the one-line stub-clearing step (`pop("stub")`,
    `ref_source: "bib"`) when the matched Reference was a stub.
  - `build_bibliography_from_source` docstring: "no References exist yet" →
    "no *non-stub* References exist yet".

- `src/pdfdrill/commands.py` (unchanged from round 0):
  - `cmd_bibliography` — the "already ran" gate excludes stubs; the
    `--force` drop path only drops non-stub References and calls
    `drop_dangling_cites`.
  - `cmd_bibsource` — the "author's bibliography is authoritative, drop
    prior References" step keeps stubs and uses `drop_dangling_cites`.
  - `cmd_bibfetch` (API and keyless-delegate paths) — pops `stub` when an
    enrichment lands, so a bibfetch-filled stub reads as filled.

- `tests/test_reference_stub.py` — 5 tests (was 4):
  - `_run_citation_processor` simplified to one `process_document(doc)` call
    (stub creation is now inline in `create_object`; there is no
    `process_objects` to also call).
  - The 4 round-0 tests unchanged in intent: 3-line fixture (`[a]`, `[b]`,
    `[a, c]`) → 3 stubs / 4 Citations, anchor-at-first-occurrence, every
    Citation linked via a `cites` Alignment (disambiguated by
    `props.citekey` since two citations from a comma list share one line
    anchor), and `add_reference_objects` filling a stub in place while
    leaving the other two untouched.
  - New: `test_bibsource_bib_fill_updates_stub_in_place` — calls
    `bibliography.load_bibtex_file` (the ~line-486 `.bib` creator
    `cmd_bibsource` uses) with a synthetic `.bib` entry for `"a"`; asserts
    `created == 0` (filled, didn't duplicate), the stub's id and anchor are
    kept, `stub` is dropped, `ref_source` becomes `"bib"`, and `b`/`c` are
    untouched. Pinned per the coordinator's ruling because the corpus
    measurement below can't exercise this path (no `.bbl`/`.bib` on disk for
    penev_A).

No prop-contract change was needed (unchanged from round 0): `stub` isn't in
the committed `corpus_props.json` snapshot (a walk of the library, last done
for task 290, not re-run here) so `table_violations()` doesn't see it yet;
`ref_source: "citation"` is a new value of an already-documented prop, not a
new prop.

## WHAT WAS LOST by `model --force`, and how to restore

Unchanged from round 0's finding: object-type counts are identical before vs.
immediately after `model --force` for every structural type (Page 22,
Footnote 53, Table 1, TableRow 15, TableCell 54, Sidenote 46, Toc 1, Abstract
1, Diagram 14, Section 37, Picture 11, ListItem 4, Equation 116, Formula 674,
Paragraph 222) — only Citation and Reference move, because `pdfdrill
bibliography`'s Citations/References aren't retracted when `BIBLIOGRAPHY_
BUILT` is dropped (HANDOVER-RULES §3, "Retraction task" — known, explicitly
out of scope here). **Restore**: `pdfdrill bibliography penev_A.pdf --force`
(done, both rounds) regenerates the 80 author-year Citations; with round 2's
fix it also regenerates all 52 stubs. The library document was left in the
round-2 restored state (81 Citations/52 keys/52 stub References), not
reverted to the pre-task backup, consistent with treating `~/pdfdrill-library`
as regenerable; backups remain at `out/010/`.

## OPEN

- **The "8 filled by bibsource" half of the spec cannot be measured** for
  penev_A: no `.bbl`/`.bib` file exists on disk for this document, and the
  earlier 8 References this document apparently had were lost to the
  retraction gap before this task started (no `BIBSOURCE_BUILT` fact or
  `bibsource_*` evidence survives either, so even reconstructing what
  produced them isn't possible from this sidecar). The fill-in-place
  behavior itself IS pinned by unit test even though the corpus measurement
  can't exercise it: `tests/test_reference_stub.py::
  test_bibsource_bib_fill_updates_stub_in_place` calls `load_bibtex_file`
  (the `.bib` creator `cmd_bibsource` uses) directly against a stub and
  asserts it fills rather than duplicates.
- `cites` Alignments accumulate duplicates across a `pdfdrill bibliography`
  run: `ensure_reference_stub` links each citation to its Reference at
  creation time, and `cmd_bibliography` unconditionally calls
  `link_citations(doc)` afterward, which re-links by citekey/number with no
  "already linked" check — penev_A's 81 Citations end up with 162 `cites`
  edges. Pre-existing shape (a rerun of `link_citations` alone already
  double-links), not introduced by this task and not in the fix-round
  checklist; flagged here rather than silently fixed.
- The retraction gap itself (HANDOVER-RULES §3) is unfixed, as instructed.
- `docs/layers/PROPS.md` / `corpus_props.json` do not yet list `stub` (new
  prop) or `ref_source: "citation"` (new value of an existing prop) — both
  require a `tools/propstable.py` run after a fresh corpus walk this task
  did not perform. No test currently requires it.
- `cmd_bibfetch`'s stub-clearing (API and keyless-delegate paths) has no
  dedicated new test; `tests/test_bibfetch_delegate.py` covers its baseline
  behaviour and passed unchanged.
