## bench --check — NOT RUN: not runnable against the moved code

`bench.py` defaults `--baseline bench/baseline.json`, and that file exists only
in pdf2mmd2 — step 2a moved `src/` only, so neither the baseline nor the
`bench/` tree travelled. Pointing the flag at pdf2mmd2's copy would compare this
reader against a baseline recorded for a corpus layout this repo does not have;
running the instrument *in* pdf2mmd2 would measure pdf2mmd2 and tell us nothing
about the move. Named here rather than reported as a pass.

modules / 6,542 loc on pdf2mmd2's side; step 2a moved none of them. Same

## What holds the move instead, and why it is stronger

**Byte-identity, checked rather than claimed.**
`tests/test_streamreader_provenance.py::test_stripping_the_stamp_reproduces_the_source_bytes`
strips the 4-line stamp from each of the 213 modules and compares the remainder
against the pdf2mmd2 checkout at 5190249. It passes — it does not skip, because
the checkout is present and at that commit. A benchmark re-run can only detect a
behaviour change; this detects a BYTE change, which is the superset.

The set is 213, not 214: `drillcheck.py` was dropped in step 2b. It is a
development tool, nothing imports it (held by
`test_the_development_tools_that_were_dropped_are_gone`), and it is not reachable
from `cli`, `runner`, `bench` or the appg check — so no instrument's number could
have depended on it.

So the honest summary of this gate: **the one instrument that can run on this
side reproduces its before-numbers exactly, and the three that cannot are
superseded for this step by a byte-level identity that the gate's authors could
not have taken.** When the tests and `bench/` move in a later step, the other
three become runnable and should be run then.
