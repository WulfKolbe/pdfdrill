WHY -- AND THIS IS THE RESULT
-----------------------------
The stream path WAS running. Every glyph on those pages carries an index
(26 of 26 spans on 91.pdf), so the fallback never fired. It bound by stream
and still refused.

Instrumented, 17 of 18 refusals on 91.pdf are the "same baseline but
excluded" branch -- NOT the off-baseline guard everyone predicted. A merged
display line contains whole sub-expressions set at script size on their OWN
baselines: a fraction's numerator and its denominator are each a little
expression with its own scripts. `_attach_scripts` models ONE baseline with
scripts hung around it. No binding rule fixes that, because the problem is
the shape of what it is being asked to describe.

SO THE PLAN IS WRONG
--------------------
    725: "attachment by stream adjacency first, then uncomment the merge"
    726: same, traced further
    696: same, from the opposite direction

Three notes, two directions, one conclusion -- and it is false. The
agreement between 696 and me was not independent corroboration; it was the
same wrong inference made twice from the same symptom, which is exactly what
it looks like when a diagnosis is right.

Recorded in structure.py at the site, not only in a note, because the next
reader of 696/725/726 will otherwise implement it a third time.

WHAT IS ACTUALLY NEEDED
-----------------------
A pass that can describe a row containing several baselines each carrying
their own sub-expression -- which is what a display line IS. `to_tex`
already recurses for fraction parts; the missing piece is recognising the
sub-expression boundaries in a row that has no rule to split on (stacked
limits, aligned columns, matrix rows).

That is a new unit and I have not designed it. What can be said is that it
is not a tweak to `_attach_scripts`.
