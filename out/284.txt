THE REPORT — BUILT AND WORKING
------------------------------------------------------------------------------
    Identifier | Page | Class | Source | Rendered | Scan

Rendered and Scan are the LAST TWO columns because `inkdrill compare` compares
the last two by default. They are given equal width: a Rendered cell narrower
than its Scan would put a scale difference into the residual, which is the one
thing the two columns exist to measure.

  Rendered  the region's own LaTeX compiled as its OWN document, rasterised by
            ghostscript at 400 dpi into standalone-regions/<ident>.png. Where
            there is no LaTeX — 25,499 of 27,287 corpus rows — the SCAN is
            repeated here and the row is marked \emph{(dup)}.
  Scan      the tex.zip image whose filename region 5-tuple matches (282),
            else the CDN crop.
  Class     the residual class beside MathPix's confidence, read back from
            report.regions.ink.json. "---" until measured, which is the honest
            state rather than a blank that reads as clean.

The two documents that fail almost everything fail for one reason, and it is
not the renderer:

    ! LaTeX Error: File `figures/ch1/concept2' not found.
    ! Undefined control sequence.        (\<v|  \>  — author macros)

The region's LaTeX references the AUTHOR's own figure files and the AUTHOR's
own preamble macros. A standalone document has neither. That is a real limit
with a known remedy — `latex_source.standalone_preamble()` already converts a
document's own preamble for exactly this purpose, and `injectlatex` has the
e-print — and it is the obvious next step rather than something this task
invented a workaround for.

THE MEASUREMENT — WRITTEN, AND IT REFUSES
------------------------------------------------------------------------------
    pdfdrill regionink <pdf> [--force]   ->  report.regions.ink.json

Renders each image-table page at 300 and 600 dpi, runs `inkdrill compare` as a
SUBPROCESS (pdfdrill consumes inkdrill, it never imports it), joins the result
to the build's own row manifest and classifies with the same `flag_of` the
equation rows use.

Beside report.ink.json, never merged into it. Each record carries:

    id · page · report_page · line
    rendered_source   "standalone" | "scan (duplicated)"
    scan_source       the tex.zip filename | "crop" | "none"
    duplicated        TRUE for a self-comparison
    has_latex · L · R · distance · comp_delta · signed_delta · flag · code

`duplicated` comes from the build's manifest, not from comparing the pixels.
A row that shows the scan twice has a distance that is a FLOOR, not agreement
between two sources, and deducing that from the numbers is exactly the
inference this task forbids.

WHAT IS NOT DONE, AND WHY I STOPPED RATHER THAN RAN
------------------------------------------------------------------------------
My page/row detection under-counts. On 0049 — 6 image rows, 5 on report page 3
and 1 on page 4 — `inkdrill compare` returns 4 rows for page 3 and 0 for page
4, because a page carrying a single row forms no detectable row lattice.

The join then REFUSED:

    REFUSING to write report.regions.ink.json: 4 measured rows against 6
    manifest rows — the pairing is unknown.

That is the correct outcome and the assert earning its place — it also caught a
real mistake of mine earlier, when I rebuilt report.tex without --compile and
the PDF on disk was a different layout. But a refusal is not a measurement.

inkdrill's own `tools/reportcompare.py` solves this for the equation table with
a 150 dpi probe, a leading contiguous run of pages whose lattice matches the
column count, a coverage check and a 40 px sliver filter. I have none of that.
Reimplementing it badly and then running it unattended across 1,351 documents
would produce quietly wrong rows in a file whose whole purpose is to be trusted
— which is the failure this session has spent its length avoiding.

So: the corpus run is not started. What it needs is inkdrill's detection, and
that is inkdrill's code.
