DEFINITIONS AS IMPLEMENTED
  THE EMITTED PROJECTION is the TiddlyWiki array, built IN MEMORY from the
  Document (`TiddlyWikiProjector.project` + its own `_assign_titles`). No
  `.tiddlers.json` is read: a stale artefact would make the audit measure
  the wrong document. Titles are compared after the projector's own
  `_sanitize_title`.

  REACHABILITY IS A BFS FROM THE ROOTS, not a scan of every tiddler's text.
  THE ROOTS, as `TiddlyWikiProjector._emit_tiddlers` writes them:
    * the DOCUMENT tiddler — titled with the bibkey, tagged `document`,
      whose body lists every TOP-LEVEL section as `- <$link to="H">cap`;
    * the TOC INDEX `<bibkey>_TOC` — tagged `toc`, the rebuilt fractal xref,
      whose rows list EVERY captioned section the same way (262).
  From a section the walk continues through its body — one content
  transclusion per child block (`{{P||PARA}}`, `{{E||EQBLOCK}}`, `{{T||TAB}}`
  …) and `- <$link to="S">{{S!!caption}}</$link>` per subsection. From a
  paragraph it continues through the inline markers baked into its text
  (`{{F||FO}}`, `{{R||CIT}}`, `{{N||FN}}`). Reached: 1141 of 1271 tiddlers on
  penev_A, 715 of 838 on penev_B.

  A PARENT is a CONTENT transclusion `{{title}}` / `{{title||TPL}}` in some
  REACHED tiddler's text. That is the only containment edge TiddlyWiki has.

  A LISTING carries the walk downwards but is NEVER a parent: the root's and
  the TOC's `- <$link to="H">`, and a section's subsection list (whose
  `{{S!!caption}}` field transclusion is the same kind of edge). The root and
  the TOC each list EVERY section, so counting a listing as a parent would
  report every section in every document as multi-parent. `<$link to="…">`
  with a literal title is followed only out of a `document`, `toc` or
  `section` tiddler — the only three places the projector emits that form; a
  `\ref`-resolved `<$link>` lives in a section's `caption` FIELD, never in
  `text`, so a cross-reference cannot parent anything.

  UNREACHABLE = the object's tiddler was never reached. `reason` is
  "no tiddler" when the projector emits nothing at all for it, else
  "not reached". Every entry also carries `named_by` — how many tiddlers
  name it regardless of whether THEY were reached — so "nothing names it"
  and "only unreached things name it" stay distinguishable.
  MULTI_PARENT = content-transcluded by 2+ distinct REACHED tiddlers.

  CLAIMED: a `mathpix_lines` anchor is claimed by an object with a `surface`
  Realization on that stream whose [start, end] contains the anchor and which
  carries no sub-anchor offset/length. An inline object (Formula, Citation,
  footnote marker) lives INSIDE a line and does not claim it — 1354 such
  inline realizations on penev_A, 996 on penev_B, correctly not counted.

TWO DEVIATIONS FROM THE BRIEF'S DEFINITIONS, WITH REASONS

  1. THE WALK. The brief says "reachable when the tiddler ... is named by
  exactly one transclusion ... in some OTHER tiddler's text, walking down
  from the roots". The two halves of that sentence disagree whenever the
  naming tiddler is itself unreached, and the walk is what the definition is
  FOR, so the walk wins. Round 0 implemented the flat half and it was wrong
  in both directions the reviewer named: an island of two tiddlers naming
  each other counted as reachable, and every paragraph under an unreachable
  section counted as reachable. Both are now failing-first tests
  (test_f_an_island…, test_g_a_paragraph_under_an_unreachable_section…).
  Nothing is hidden by the choice: `named_by` on every entry is exactly the
  number the flat rule would have reported.

  2. CONTAINER_TYPES = ("Page",). Read literally, the brief's claim rule
  makes a Page a claimant: `PageProcessor` gives every Page a `surface`
  realization spanning EVERY line of the page with no offset. All 3178
  penev_A anchors would then be doubly claimed (Page + the real owner) and
  the measure would say nothing. A Page's range is a container by
  construction, not a claim on content. The exclusion is printed in the
  command's own output (`container types not claiming: Page`) rather than
  hidden in the code, and is pinned by
  tests/test_conserve.py::test_page_containers_do_not_claim_the_lines_they_span.
  `List` was in this tuple in round 0 and EXCLUDED NOTHING: `cmd_lists`
  (commands.py ~9751) builds a List DocObject with no realization of any
  kind, so the entry asserted a shape that does not exist. Dropped — an
  inert exclusion is worse than none, because a reader takes it for a
  measured fact.

TWO MEASURES ADDED BEYOND THE BRIEF'S THREE (both cheap, both in scope)
  TITLE COLLISIONS — 2+ objects assigned ONE tiddler title. Nothing is lost
  and nothing is unreachable; the content is MIXED UP, which is the other
  half of the claim, and none of the three headline counts can see it.
  644 fixed the only producer (see the delta below), so this now reads 0 on
  both documents — the measure is exercised on a healthy document here and
  on a colliding one in the unit test.
  DARK ANCHORS — lines whose EVERY claimant is an unreachable object. The
  line is claimed, so the unclaimed count does not see it, and it still
  reaches no tiddler. This is the number that joins the two halves.

THE BIGGEST CLASSES, WITH EXAMPLES

  1. Citation: 81 of 81, "no tiddler" (penev_A).
     EXACTLY the user's number, and unchanged by 010/639/644. The projector
     assigns no title to a Citation object at all: the in-text marker is
     rewritten to point at the REFERENCE tiddler (`{{penev_A_REF_key||CIT}}`)
     and the Citation itself is never emitted. Arguably correct by design —
     the citation IS the marker — but by the definition it is 81 model
     objects with no image in the projection, and nothing said so before.
     Example: the `dB` Citation on p8 (a units-abbreviation false positive
     from `CitationProcessor`'s `[key]` scan, already named in 639).

  2. Footnote: 36 (penev_A) / 20 (penev_B) unreachable, `named_by == 0` for
     every one of them. Post-644 each Footnote has its own tiddler, and two
     thirds of them are transcluded by NOTHING AT ALL: the marker the body
     belongs to was never matched in any paragraph. 200 (A) / 144 (B) dark anchors — the
     largest single block of lost body text on both documents.

  3. Formula: 41 (penev_A) / 44 (penev_B) "not reached".
     A Formula tiddler is emitted but nothing reached transcludes it. On
     penev_A all 41 have `named_by == 0`, and 8 are on page 2 — the Contents pages: `(T=87)`,
     `3.11 S-U`, `1(T=1038`, `3.13 \log` (see class 4). On penev_B 30 have `named_by == 0` and
     the other 14 have `named_by == 1` — named only by an unreachable
     paragraph, which is the walk's own finding above.

  4. Toc: 1 object, "no tiddler" — 288 DARK ANCHORS (penev_A).
     The single Toc object claims lines 71..361 (pages 2–3, 291 lines) and
     the projector deliberately emits nothing for a Toc (262: the objects
     are `derived`, and one rebuilt `penev_A_TOC` index is emitted from the
     Sections instead). Those 288 lines are claimed — so `unclaimed` cannot
     see them — and reach no tiddler. 23 Formulas are hosted on those lines.
     This is the third of the user's three day-one findings, confirmed and
     now measured: the Contents region really does reach nothing, and the
     maths in it really is orphaned.

  5. Footnote+Paragraph: 34 (penev_A) / 51 (penev_B) doubly-claimed anchors.
     The user's "29 footnote bodies carry a neighbour's text", measured:
     34 and 51. A Footnote's `surface` realization and a Paragraph's cover
     the same line, so the same OCR text is in two objects.
     penev_B's doubly-claimed set is ONLY this pair — 51 of 51.

  6. Paragraph+Reference: 31 + 4 + 1 + 1 = 37 anchors (penev_A only).
     NEW SINCE THE USER MEASURED. 010 anchors a stub Reference on the
     CITING prose line, so 37 body lines are now claimed by a Paragraph and
     by one to four Reference stubs at once. Not a regression in the
     bibliography — a consequence of putting the stub in the model — but it
     is content mixed up by the definition, and it did not exist before 010.

  7. Reference: 12 of 52 "not reached", `named_by=0` (penev_A).
     All 12 are stubs whose citekey is never substituted into any paragraph.
     Cause, read off the model: a multi-key citation group produces several

CONCERNS

  the classes above rest on penev_A alone. A second citation-bearing
  document would test them; none was in scope here.
  `dark anchors` and `title collisions` are measures added beyond the
  brief's three. They are reported separately and are not folded into
  `conserved`, which stays exactly the brief's three counts.
  The command was run on the models AS THEY STAND; no `--force` rebuild was
  done, so these numbers describe the current library state, not a fresh
  extraction.
