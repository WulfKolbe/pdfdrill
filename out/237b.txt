THREE WRONG VERDICTS I HAD TO WITHDRAW BEFORE REPORTING
------------------------------------------------------------------------------
Each came from a grep that could not have returned the right answer, and each
one read like a finding.

1. "_page_range, _same_line, _overlap have NO CALLERS." They are private
   helpers used only inside pdfminer_layer.py, and I had excluded that file
   from the search. Counting internal calls: 2, 1, 1.

2. "layer_detect.has_geometry has NO CALLER outside its own module." The four
   external hits for the bare name are three uses of a LOCAL VARIABLE
   `has_geometry = bool((out.get("meta") or {}).get("pages"))` inside cmd_model
   — an unrelated thing with the same name — plus one docstring in a test. So
   the name-grep was right and the conclusion was wrong in both directions at
   once: the hits were not callers, and the absence of hits was not absence of
   callers.

3. "No dynamic dispatch by name." I grepped for getattr(, globals() and the
   string "has_ and found nothing. The dispatcher is `present(layer, doc, ...)`
   with an explicit if/elif chain — no name construction at all, which is
   exactly why a search for name construction could not see it. That chain is
   what makes has_bibliography, has_geometry, has_expanded_math and has_compare
   live; all four look uncalled to any direct search.

The pattern is the one this sequence keeps producing: a search whose shape
cannot express the answer returns an empty result, and an empty result reads as
a finding. The verdict "dead code" is especially exposed to it, because the
evidence for dead code is an ABSENCE, and absence is what a mis-shaped query
returns by default.

WHAT WOULD ACTUALLY BE DEAD, AND IS NOT
------------------------------------------------------------------------------
For pdf_lines to be dead, cmd_eqnums, cmd_lists, cmd_tables, cmd_model and
cmd_abstract would all have to stop reading it. All five are registered in
commands.yaml and all five ran in the out/213 drill chain over eleven
documents.

For the pdfminer path to be dead, cmd_mathpix would have to stop calling
_stream_born_digital_lines and _pdfminer_char_dump. It calls both — the
born-digital lane is what produced ConformalGeometryOfSimplicialSurfaces' first
markdown this evening, before the MathPix outputs replaced it.
