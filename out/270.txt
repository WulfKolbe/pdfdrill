270 — the value emitted as content, not as an attribute
==============================================================================

THE FIX, AND WHY IT RUNS FIRST
------------------------------------------------------------------------------
The bodies are self-closing widgets carrying the value in an attribute:

    <$image source={{!!canonical_uri}} width={{!!width}} height={{!!height}}/>
    <$latex text={{!!latex}} displayMode={{!!displayMode}} />

`_IMAGE_RE` wants `source="…"` (quoted) and `_LATEX_RE` wants
`<$latex>…</$latex>` (paired), so neither matched. `_rewrite_transclusions` ran
first and resolved the field correctly, leaving a bare unquoted URL or a LaTeX
string, and `_ANY_WIDGET_RE` then stripped the whole tag — taking the resolved
value with it. The resolution had succeeded; the result was discarded one line
later.

`_self_widgets_to_markdown` runs BEFORE transclusion resolution, while each
attribute is still the single unambiguous token `{{!!field}}`, and emits the
value as CONTENT:

    <$image source={{!!canonical_uri}} …/>   ->  ![](https://cdn…/a-1.jpg?h=1&w=2)
    <$latex text={{!!latex}} displayMode=… />  ->  $E = m c^{2}$  /  $$ … $$

Order is the whole point. Once the URL is inlined the attribute cannot be
delimited again without guessing where it ends, and a LaTeX body legitimately
contains spaces, `>` and `/` — `\max _{x}\left[\sqrt{a/b}\right)^{2} > 0` has
all three. Nothing is left in an attribute to lose.
