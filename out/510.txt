AND IT FOUND A DEFECT I HAD PUT THERE
--------------------------------------
The rebuild still showed `\mathcal{J}`. The join was not stale — my own 502
edit was incomplete.

`refine.record_one` writes an accepted refinement in TWO places: the object's
twin prop `latex_refined`, AND a realization with `provenance="change"`
carrying the same value plus `verified_by`. `refine.evidence_for` requires
BOTH and requires them to AGREE:

    if rp.get("verified_by") and rp.get(REFINED_FIELD) == props[REFINED_FIELD]

502 changed only the prop. So the two disagreed, `chosen_latex` found no
matching evidence, and **the refinement had become invisible to every
projection** — the row would have reverted to `\mathscr{g}`, which renders
nothing at all because rsfs10 has no lowercase. A withdrawal that silently
un-accepted the correction it was refining.

Fixed: the realization now carries `\mathscr{J}` and `verified_by:
source+ink`. `chosen_latex` returns `\mathscr{J}` and the rebuilt page shows
it. The docpack was invalidated rather than edited, per 276.

This is the failure class already on the list — a fix that covers the data
path and not the evidence path is half a fix — and it is worth noting that
nothing caught it for a day. `evidence_for` refuses silently: a refinement
with a mismatched realization is treated as no refinement, not as an error.
