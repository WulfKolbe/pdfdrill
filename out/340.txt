340 - the fifth column, and the sidecar that records what is typed into it
==========================================================================

THE COLUMN SPEC

  The image table gains one column, fifth, between Source and Rendered:

    Identifier | Page | Class | Source | AUTHOR SOURCE | Rendered | Scan

    \begin{longtable}{|p{20mm}|p{7mm}|p{12mm}|p{Dmm}|p{Amm}|p{Rmm}|p{Smm}|}

  where D = 22% of the free span, A = 16%, and R and S split the rest
  equally -- the two image columns keep equal width because comparing them
  is the point, and a Rendered cell narrower than its Scan would put a
  scale difference into the residual.

  The table is now SEVEN columns wide, not six. That is worth knowing
  downstream: inkdrill selects a table by column count, and a 7-wide
  region table no longer collides with a 6-wide equation table the way
  295 recorded (six_col_tables=2 on nearly every rebuilt report).

  Each cell ships as

    \authorsrc{texzip/<process-id>/images/<process-id>-<page>_<h>_<w>_<y>_<x>}

  which renders the MathPix crop. A person overwrites the filename with
  the author's own figure file and recompiles. An untouched report shows
  the crop twice, so unedited rows are visible at a glance.

  \authorsrc is a MACRO, not a bare \includegraphics, so the harvester
  looks for one thing and cannot mistake an ordinary image for an edit.

THE SIDECAR

  <stem>.figpairs.json, beside the PDF -- deliberately the same shape as
  <stem>.notation.json (103), down to `present` being distinct from
  `entries == []`. Both answer the same kind of question: editorial
  knowledge about ONE document, recorded rather than inferred.

    {"version": 1, "bibkey": "...",
     "entries": [{"crop": "...", "base": "...", "identifier": "...",
                  "page": "...", "contested": true}]}

  `pdfdrill figpairs <pdf>` harvests report.tex into it. Absent is normal
  and is NOT an error.
