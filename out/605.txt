THE MECHANISM, PROVEN

  \zsavepos alone records posx/posy and NOT the page.
  \zref@labelbyprops alone records the page and leaves posx/posy at ZERO,
  because it never emits the \pdfsavepos whatsit.
  Both, in that order, is the only form that yields all three:

      \pdrowpos{#1} = \smash{\hbox to 0pt{%
          \pdfsavepos\zref@labelbyprops{#1}{posx,posy,abspage}\hss}}

  Two per row: one before the identifier cell, one after the last cell.
  Labels are a counter (pdr00001a/b), not the identifier - identifiers carry
  `.` and `_` and run to 60 characters. The mapping is in the manifest.

  sp -> bp uses 65536 * 72.27 / 72. TeX measures y UP from the page bottom
  and so does PDF user space, so y passes through unchanged; page_height_bp
  is carried so a consumer working from the top need not guess the paper.

AND A SECOND FINDING THAT BLOCKS POSITIONAL SELECTION ANYWAY

  compare_page returns rows carrying only:

      ['L', 'R', 'a_eq_b', 'dis', 'line', 'page']

  No geometry. Pairing a lattice row to a rect needs the row's y-extent, and
  inkdrill does not return one - `line` is an ordinal within the page. So
  the rect makes the pdfdrill side positional and the join still cannot be
  completed until compare_page reports each row's vertical extent.

  That is the ask, and it is small: the lattice already knows where it cut.
