649 — EQBLOCK becomes EQ; the dead EQ template goes
====================================================

THE RENAME. `tiddlywiki.TEMPLATES["EQBLOCK"]` (the display-equation widget)
is renamed to `TEMPLATES["EQ"]`. The dead inline-link template that used to
occupy the key `"EQ"` ("see Equation 1.1", own comment: "not currently
emitted by any substitution") is dropped outright — FREF already does the
equation-reference job (188 uses on penev_A, 647b). `BLOCK_TEMPLATE["Equation"]`
follows: `"EQBLOCK"` -> `"EQ"`. TEMPLATES goes from 16 keys to 15.

No collision with 644's TITLE_SHAPES, which also uses the prefix `EQ` for an
Equation object's TITLE: a title always sits before `||` in a transclusion
marker and a template name always after it
(`{{<bibkey>_EQ0001||EQ}}`) — the two namespaces are already disjoint by
position, the same anchor 644's guard test relies on.

THE ALIAS QUESTION, SETTLED BY MEASUREMENT. The brief's ruling was
conditional: add `TEMPLATE_ALIASES = {"EQBLOCK": "EQ"}` (read wherever a
transclusion's template is read, counted, and rewritten by the next `clean`)
ONLY IF materialised `{{…||EQBLOCK}}` text already sits in `props["text"]`
on disk. Measured BEFORE any change, both documents' `model.docmodel.json`,
every object, every string-valued prop field:

    penev_A                                           0 occurrences
    SteerableWaveletFramesBasedontheRieszTransform     0 occurrences

Read out of the mechanism, not just the count: `clean` ->
`heading_cleanup.materialize_transclusions` only ever rewrites a PARAGRAPH's
`props["text"]` from the TiddlyWiki projector's own re-projection of that
paragraph. A display Equation is never inlined into a paragraph's text —
it is a structural child of a Section, reached by `section.children` (the
`BLOCK_TEMPLATE` mechanism), never by an inline marker inside prose. So
`{{…||EQBLOCK}}` could not have been materialised into either document's
model, in principle, not just in this sample. The alias is therefore dead
code for a population of one: dropped. No `TEMPLATE_ALIASES`, no
`template_alias_used` counter, no rewrite-on-`clean` step, and no test for
any of it — there is nothing on disk for it to fix.

A LATENT NAMING RISK, NOTED AND NOT FIXED (out of scope; measured harmless
on both documents). `pdfdrill/commands.py:_MARKER_RE` (`cmd_spoken`) matches
only templates `(FO|EQ|FREF)` by design (comment: "renders FO/EQ/FREF into
speech and leaves every other template's marker ALONE"). Before this task
`EQ` there meant the dead inline-link template (0 uses anywhere); after the
rename it means the display-equation widget. If a future `clean` ever DID
materialise a display equation inline into a paragraph's text — it cannot
today, per the mechanism above — `cmd_spoken` would now read its `spoken`
field instead of leaving it as an uncounted literal marker. Not a regression
on any document measured (0 occurrences before and after), but a naming
coincidence worth a future reader's attention: this pattern was never a
literal `"EQBLOCK"` and so was invisible to the grep this task ran from.

WHY THE LaTeX OUTPUT IS BYTE-IDENTICAL, NOT JUST UNCHANGED IN COUNT. This
was checked, not assumed (rule 14: re-measure against the current artefact).
`latex.py`'s own `_render` for an Equation object does NOT go through the
`{{…||EQ}}` transclusion-marker path at all: it renders directly,
`self._title_index.get(obj.id)` -> `\EqExpr{i}`, wrapped in
`\begin{equation}…\end{equation}`, exactly the way Table/Picture/Diagram
render by direct type dispatch in the same method. The
`_template_handlers()["EQ"] = self._math_token` entry (640-a's branch
table) exists for the OTHER case — a `{{…||EQ}}` marker already baked
literally into some paragraph's text by `clean` — and, per the alias
measurement above, that case has zero instances in either document. So the
rename touches a template name that the LaTeX projector's own compiled
output never spells out for these two documents; the `.tex` files could not
have differed. `latex/stages/05-templates.json`'s `counts` block confirms
this independently: it shows `resolved:FO`, `resolved:CIT`, `resolved:FREF`
on both documents and never `resolved:EQ` (nor, before, `resolved:EQBLOCK`)
— the marker-resolution counter is never incremented for either template
name because no such marker is ever substituted through that path on
either document. The 116/70 EQ transclusions counted above live entirely in
the TiddlyWiki JSON projection (`cmd_tiddlers`), not in the LaTeX one.

The compiled PDFs were rebuilt (`xelatex`, 2 passes) as part of
`cmd_latex --force --compile` and recompiled cleanly on both documents —
this is a rebuild of an unchanged artefact, not a new one, and no page
count or error count changed (penev_A 0 errors; Steerable's one
pre-existing `\bibitem{Unser2008}` error, 640-f, unrelated to this task, is
unaffected either way).
