D. WHAT MADE THE NUMBER WRONG, AND WHY A DATE CANNOT FIX IT

A model's meta block holds bibkey, source_path, source, num_pages, title,
root_id. It records nothing about the code that built it. So the only
generation marker available is the file's mtime - and mtime cannot tell
'built from committed HEAD' apart from 'built from an uncommitted working
tree that later became HEAD'. The fourteen 15:10 models are stale by
timestamp against a commit made at 15:13, yet they were built from the tree
that commit captured. The table in section A is therefore honest about dates
and silent about code. A build stamp in meta - commit sha plus a dirty flag -
is what would make the question answerable.

This applies to more than sections. Any corpus number summed across
per-document artefacts inherits the oldest generation in the set, and nothing
in the artefact says which generation that is.
