WHAT IT ACTUALLY IS — OUR MACRO EXPANDER TAKES THE WRONG DEFINITION
-------------------------------------------------------------------
The author defines \bS TWICE, in two different files:

   texsrc/_definitions.tex:247      \def\bS{\begin{slide}}
   texsrc/jin_thesis_macros.tex:32  \def\bS{\mathbb{S}}

and main.tex inputs them in this order:

   main.tex:76   \input{_definitions}
   main.tex:77   \input{jin_thesis_macros}

TeX semantics are LAST DEFINITION WINS, so in the real document \bS is
\mathbb{S} — the state space — and the author's PDF is correct. main.tex:183
says so in prose: "The {state-space} $\bS=\{1,2,\hdots,d\}$ is finite."

src/pdfdrill/latex_source.py:430 collects \def with

   macros.setdefault(m.group(1), {...})

i.e. FIRST definition wins. We therefore expanded 168 uses of \bS with the
slide shorthand instead of the state space. The author's source is fine; the
expansion is not.

THE FIX, AND WHY IT IS NOT A ONE-LINE CHANGE
---------------------------------------------
Changing setdefault to plain assignment makes \def last-wins, which is correct
for \def against \def. But the collector processes \newcommand and \def in
SEPARATE passes, so plain assignment would let a \def anywhere in the preamble
override a \newcommand that came after it in the source — trading one
order-independence bug for another.

The correct fix is a single pass over all definition forms in SOURCE ORDER,
last wins, which is what TeX does. That is a real change to collect_macros and
wants its own task rather than being folded in here.

Scope of the bug beyond this document: any source that redefines a macro. This
is the only document where it produced a visible artefact, because \begin{slide}
does not typeset — a redefinition that expands to something plausible would be
silently wrong instead.
