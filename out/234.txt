WHAT EACH CHECK REFUSES, AND WHY THAT WORDING
------------------------------------------------------------------------------
Every check names what it looked at, and **a check that cannot see its input
FAILS** rather than passing quietly. out/213 had six reports exit 0 with glyphs
silently discarded; a gate has to be harder to satisfy than the thing it
guards. A document with no report.log fails `glyphs` with "no report.log — the
report has not been compiled, so nothing can be said", not with silence.

Two of the five needed a semantics decision rather than a presence test:

**A quarantine older than the measurement beside it is SUPERSEDED.** 0902.0431
carries report.ink.json.MISPAIRED from 08-24 next to a report.ink.json from
08-26 that paired. A flat "any quarantine vetoes" rule would call that document
broken on the strength of a failure that has since been redone. Only a
quarantine that is the most recent word still vetoes — then the last thing that
happened was a failure to pair.

**A residual distribution with no variation is a pairing failure, not a
result.** This is the 0902.0431 answer below, and it is now a check.

TWO THINGS THE MANIFEST WAS MISSING, FOUND BY DECLARING THE DEPENDENCY
------------------------------------------------------------------------------
`publishready` reads report.log, report.tex and report.pdf, so it declares
`requires: reporttex`. Two tests refused that, and both were right:

**reporttex had no done_when.** The planner treated it as never satisfied, so
it could not be named as anyone's prerequisite — CLAUDE.md's "a dependency that
is not in the manifest is a hope", from the other side: a producer nobody can
depend on. It now declares `artifact:report`, which checks both files exist,
the pdf is not older than the tex, and NEITHER IS EMPTY. The pages repo's CI
learned the last part the hard way ("the guard checked names, so a zero-byte
report.pdf passed it").

**reporttex recorded no fact.** It wrote evidence and never called add_fact, so
the capability graph had nothing to resolve a prereq against. It now records
REPORTTEX_BUILT with a logged transition.

Not REPORT_BUILT — that constant already exists and belongs to `report`, the
prose/markdown report. I reused it by accident and caught it on the next grep:
one fact for two commands would let either satisfy a prerequisite meant for the
other, silently. Distinct name, distinct fact.
