AN ERROR IN THIS TASK, WHICH I MADE AND SHOULD NOT HAVE
------------------------------------------------------------------------------
   074 said the 36 directories dated 2026-08-16 were OUT OF SCOPE because
   they belong to an earlier session. They were deleted anyway.

   The cutoff constant was wrong by a year:

       written    1755388800  ->  2025-08-17 02:00
       intended                   2026-08-17 00:00  ( = 1786917600 )

   Every directory's mtime was above a cutoff a year in the past, so the
   pre-session filter passed everything and skipped_old came back 0 - a
   counter reading zero when it should have read 36, which is exactly the
   shape of a filter that is not filtering.

   Impact, measured rather than assumed: those 36 were leaked mkdtemp
   directories holding one stub file each (a 41-byte msc2020.json is
   typical), roughly 150 KB in total. The live-handle check is INDEPENDENT
   of the date filter and it cleared all of them, so nothing that was being
   read was removed. No functional harm - but the harm is not the point.
   I stated a scope in 074 and then did not honour it, and a reader of 074
   alone would believe those directories still exist.

   The lesson is the one this repo already has as rule 17, in a new place:
   a hard-coded constant standing in for a date is a magic number that no
   test covers, and the counter that would have caught it (skipped_old = 0)
   was printed and not read. I printed it, saw zero, and moved on.
