THREE DEFECTS FOUND BY BUILDING THROUGH THE CLI INSTEAD OF A SCRIPT
-------------------------------------------------------------------
1. `--findings` did not exist on the command surface. reporttex put the
   unknown flag into the pdf-argument list and discarded it, so the first
   "findings build" was the full 284-page report. An unknown flag is
   accepted and ignored, which is the failure mode that makes a wrong
   build look like a right one.

2. The ink join was computed with `sc.blob_dir.name` as the bibkey while
   build_report used `resolve_bibkey`. Since 462 renamed the identifier
   stems and not the folders, every renamed document printed

     INK JOIN FAILED: none of the 1670 measured identifiers matches a
     row of this report (0 rows)

   on every build. The check that exists to catch a join failure was
   itself always failing, on exactly the documents it guards. Fixed to
   the same resolution build_report uses; johnston now joins 1,670 of
   1,670.

3. build_report computed the four section counts and dropped them, so
   the caller reported "1670 display equations" for a report showing 52
   rows. Returned as the `findings` key and printed first.
