THE CONSTRAINT, AND WHAT IT ACTUALLY CONSTRAINS
------------------------------------------------
"The corrected-pair layout must come from the same code that builds a
corrections.html row."

What can be shared is the SELECTION and the ROW MODEL. What cannot is the
rendering: corrections.html sets a pair as HTML with an inline SVG or KaTeX,
report.pdf sets it as two longtable rows. Those are different jobs, and
pretending one function does both would be its own kind of drift.

So `src/pdfdrill/corrections.py` now holds the selection and the identity,
and both artefacts read it:

  pairs_in(doc_dir)      every accepted correction in one document
  collect(lib)           every accepted correction in the corpus
  identifier_for(rec)    the report identifier, via the region
  crop_path(rec)         ONE crop, shared by both halves of the pair

`tools/corrections439.py` lost 70 lines and now imports them. It still
produces 33 rows at the same size, which is the check that the extraction
changed nothing.

TWO DEFECTS THE EXTRACTION EXPOSED
-----------------------------------
Both were live in corrections.html, and both were found only because the code
was made to serve a second reader.

  1  THE IDENTIFIER JOIN RETURNED A PAGE. `props.region` is absent on 1 of 33
     corrections — 0707.4470_FO0175, the one 502 repaired — so the lookup key
     became ('029','None','None','None','None') and matched whatever tiddler
     was also all-None. It returned `0707.4470_PAGE_029` for a Formula.

     Same trap as 492's `props["top_left_x"]` on 0 of 70,000 objects: the
     region is on the realizations. `pairs_in` now resolves it through
     `object_geometry`, and an all-None key is REFUSED rather than matched.

  2  AND THE REGION ROUTE CANNOT WORK FOR INLINE FORMULAS AT ALL. An FO
     tiddler carries no region — 488 measured the same absence on page and
     confidence. So FO0175 still had no identifier after the first fix.

     A unique `latex` match is exact and is now the fallback. A REPEATED
     latex is dropped rather than guessed at, which is tested.

     33 of 33 identifiers now resolve; FO0175 returns `0707.4470_FO0175`.

ONE RULE THAT NEEDED STATING
-----------------------------
A corrected row is EXCLUDED from unresolved even when its original does not
render. 502's pair is exactly that case: `\mathscr{g}` renders nothing at all,
because rsfs10 has no lowercase. Without the exclusion the same row would
appear twice — once as a correction and once as a failure — and the pair
already says what was wrong. Tested.
