THE FOUR BLOCKERS THAT WERE NOT ON THE LIST

1. `_bail` was USED BEFORE IT WAS DEFINED. Step 2b calls it; it was defined
   forty lines lower. Python binds a name assigned anywhere in a function
   for the whole function, so the call raised UnboundLocalError, the
   handler never ran, and report.pdf was left as the 1-page phase-1
   scaffolding - on exactly the document that needed the refusal. A guard
   placed after the code it guards is not a guard.

2. `--pages` WAS NEVER PARSED. cli._do_inkreport did not look for it, so
   `--pages 10` fell into the positional list, where _pdf() takes args[0]
   and ignores the rest. Every 'the 21 at --pages 10' run so far was an
   unbounded run. This is 516's --findings defect in a second command.

3. cmd_inkreport REBOUND ITS OWN `pages` PARAMETER. One line computing an
   estimate for the PLAN message assigned to `pages`, so the resume test,
   all three builds and the stamp received the estimate instead of the
   bound. `--pages 7` resumed a measurement stamped pages_bound=2.

4. cmd_reporttex REBOUND ITS OWN `pages` PARAMETER, twice, via
   `pages, errors, demoted = res` - the number of pages the compile
   PRODUCED. The stamp then recorded pages_bound=2 for a --pages 10 run,
   and the resume compared a built count against a requested bound as
   though they were the same question.

And one found by fixing 1:

5. `_bail` REBUILT WITH THE INK STILL STASHED. Step 2 hides
   report.ink.json and restores it in a `finally`; `_bail` is called from
   inside that `try`, and a `return` evaluates its expression BEFORE the
   `finally` runs. The restored reading build therefore had no ink. On
   Bradley that replaced a 2-page report carrying ink with a 1-page one
   carrying none: the handler written to stop a failed run making things
   worse was making them worse. Now it un-stashes first, and Bradley's
   restored build is phase=reading, 2 pages, ink_adopted=true.

A page bound is also a CONTENT question for the resume, so `pages_bound`
is now written into the build stamp and compared by fresh_ink alongside the
formula rule and the model sha. Without it the first bounded run on every
document would have resumed an unbounded measurement and reported READY -
463's defect arriving through a new flag.
