641 — a superscript citation becomes \cite, and how it differs from a footnote marker
====================================================================================

THE ANSWER TO "HOW DID YOU TELL THEM APART", FIRST, BECAUSE IT IS THE TASK
  A footnote marker has a BODY on its own page. A citation superscript has a
  NUMBERED BIBITEM and no such body. The maths is identical — MathPix writes
  both as an empty-base `\({ }^{n}\)`, and nothing in that string distinguishes
  them — so the document decides, in this order, first rule wins:

    a. a Footnote with refnum n whose body page is the marker's page (or +1,
       within MAX_SPILL_PAGES)              ->  \footnotemark[n]        (638)
    b. else, and only when the reference list is NUMBERED at all, a Reference
       with props["number"] == n            ->  \cite{<citekey>}        (641)
    c. else the marker stands byte-for-byte and is counted.

  A marker that matches BOTH is a FOOTNOTE. A numbered reference list and
  footnotes on the same page both exist in one document, so the collision is
  real; the footnote body being physically on that page is the stronger
  evidence than a bibliography entry that merely carries the same integer. The
  collision is COUNTED (`marker_both`), not decided in silence.

  Rule (b) is gated on the document, not on the marker: it cannot fire unless
  at least one Reference carries a printed `number`. penev_A is author-year —
  52 References, 0 numbered — so on that document rule (b) never fires, which
  is the designed outcome and is why `references_numbered` is printed beside
  the counts (0 = the rule cannot fire at all).

WHAT IS OPEN
  641-a  THE MATERIALISED LANE DOES NOT ASK 641's QUESTION. After `clean`, a
         marker whose refnum names a Footnote becomes `{{…||FN}}` (identity —
         no disambiguation needed, correct) and a marker whose refnum names
         NOTHING becomes `<sup>N</sup>`, which `latex_pipeline.
         resolve_sup_markers` turns into `\footnotemark[N]` unconditionally
         (640's ruling: "a mark with no body IS \footnotemark[n]"). That
         second population is exactly rule (b)'s: a marker with no footnote
         body. On a cleaned NUMERIC-citation document a citation superscript
         would therefore print as a footnote mark and rule (b) would never see
         it. MEASURED on penev_A: 44 `<sup>N</sup>` in running text over the
         numbers 4, 6, 7, 10, 14, 15, 16, 19, 22, 26, 28, 30, 32, 34, 39, of
         which **0** name a numbered bibitem — because penev_A has none. So
         extending the rule there changes nothing on this corpus today, which
         is why it was not done under a brief that says "do not add a third
         marker walker". It needs a cleaned document with a numbered
         bibliography to be worth anything, and there is not one here.
  641-b  NEITHER DOCUMENT EXERCISES RULE (b) END TO END. Steerable has the
         gate open (29 numbered References) and no bare markers; penev_A has
         the markers and the gate shut. The rule is therefore demonstrated on
         fixtures only. That is stated, not disguised: the corpus number is 0
         and the reason is the corpus.
  640-c  penev_A.bib IS STILL NOT ON THIS MACHINE. `bibsource` ran with no

CONCERNS
  The headline number of this task is zero on both documents, and it is a
  zero of two kinds that must not be read as one: Steerable has no superscript
  citations to convert, and penev_A has no numbered bibliography to convert
  them against. Only the second would move if the corpus changed.
  The `marker_both` tie-break is a judgement, and it is the one thing here
  that could be wrong on a document neither of these two resembles: a paper
  that numbers its references AND footnotes its pages will hand a marker whose
  n is both, and this rule always calls it a footnote. The reason is stated
  (the body is physically on the page; the bibliography number is only an
  integer) and the case is counted so a reader can see how often the tie-break
  was needed. On this corpus it was needed 0 times, so the rule is untested
  against reality.
  Rule (b) does no page reasoning at all — a bibitem has no page — so it is
  strictly weaker evidence than rule (a), which is why it runs second and only
  on what rule (a) declined. A document whose footnote bodies MathPix failed
  to capture (penev_A's 42-marker class) would, with a numbered bibliography,
  see those markers become `\cite` on the strength of a matching integer
  alone. That is the failure mode to watch, and the gate plus the ordering are
  the only things holding it: it is not a proof, it is a priority.
