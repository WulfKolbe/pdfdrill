fill_ink_fields.py DOCSTRING — CORRECTED, AND MORE WAS WRONG THAN THE COMMAND
-----------------------------------------------------------------------------
   1. The build command. This report needs xelatex: it loads fontspec, and
      pdflatex aborts with "Fatal Package fontspec Error ... requires either
      XeTeX or LuaTeX" and writes NO pdf. A pdflatex flow cannot produce the
      file the script then patches.

   2. The LaTeX line it recommended. The docstring gave

         \pdfcatalog{/NeedAppearances true}

      \pdfcatalog is a pdfTeX PRIMITIVE and is undefined under xelatex —
      tested: "! Undefined control sequence", build fails. So that line could
      never have run in this pipeline. The xelatex equivalent, tested and
      confirmed to set /NeedAppearances true in the built PDF, is

         \special{pdf:put @catalog <</NeedAppearances true>>}

      It is optional anyway: the script already writes /NeedAppearances onto
      the AcroForm dict, which is what a viewer reads. The tester never used
      either line.

   Both corrections are in ~/Downloads/fill_ink_fields.py (original backed up
   to scratchpad/fill_ink_fields.py.bak). No code changed — docstring only.
