A DEFECT FOUND BEFORE ANYTHING WAS RENAMED
------------------------------------------
`rename` retargeted model, sidecar, tiddlers, report.tex and (since 394)
report.regions.json. It did NOT retarget:

  report.ink.json     266 row ids on voloshin-hypergraph
  report.tables.json  2,999 identifiers on the same document

Both are joined against the report BY IDENTIFIER and neither is rebuilt by a
rename. `residual_colour` matches report.ink.json's row ids against what
report.tex emits; after a bibkey rename the ink names the old document and the
report names the new one, so the two populations cannot intersect — 0 of 266
matched — and a document in which every row was measured renders as one in
which nothing could be. That is exactly the shape 394 wrote up for
report.regions.json, in the file the colour actually comes from.

`inkmeasure.equations_table` reads report.tables.json to find the Display
equations table, and a measurement joins its `identifiers`.

So `_retarget_ink` and `_retarget_tables` were written first, with six tests
including one that asserts the ink ids and the manifest identifiers still
INTERSECT after a rename — 0 matched being what the un-retargeted version
gives. Then the renames ran.

Found by asking what else carries the key, not by running the rename and
auditing afterwards. 394 was found the second way and says so.
