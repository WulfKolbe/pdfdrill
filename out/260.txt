WHY THE FIRST TWO DIMENSIONS COULD NOT SEE IT
------------------------------------------------------------------------------
250 asked whether every TYPE is named. 255 asked whether every FIELD is read.
Both were green while 1,239,021 `subtype` values did nothing: `text` was a
claimed type, `subtype` became a claimed field, and no check in the repo could
look one level further down. A contract that stops at the field certifies the
container, not the contents.

VIOLATIONS FOUND
------------------------------------------------------------------------------
Two, and both were live losses rather than merely undeclared ones.

  1. `algorithm` — 6,192 lines, 202 documents, the 4th largest subtype value
     in the corpus, and 6,108 of them (98.6%) were being DESTROYED by our own
     code. DiagramProcessor wrote

         "subtype": "code" if code else payload.get("subtype", "")

     so any diagram whose body is a fenced block had MathPix's own word for
     what it is overwritten by ours. 68 `pseudocode` values went the same way.
     Seven projectors branch on `subtype == "code"` to avoid compiling a
     listing as TikZ, so the assignment itself is right and could not simply be
     reverted — the defect was that one field was carrying two different
     claims. Both are kept now: `subtype` stays our classification,
     `mathpix_subtype` carries MathPix's, never overwritten.

     6,176 values recovered.

  2. The chart kinds — 2,057 lines in 320 documents. A `chart` line states
     which kind of chart it is (line 967, analytical 445, column 315,
     scatter 265, bar 60, area 4, pie 1). It reaches PictureProcessor's inline
     path, which read the line and built a Picture without ever looking at
     `subtype`. The value was in the payload in hand and dropped one statement
     later. Now carried as `mathpix_subtype`.

     2,057 values recovered.

Neither would have been caught by 250 or 255: `chart` is a claimed type,
`subtype` is a claimed field, `Picture` is a real object, and the pipeline was
green throughout.

SCOPE, STATED RATHER THAN QUIETLY NARROWED
------------------------------------------------------------------------------
A value contract only means something for a field with a closed vocabulary —
"every value of `text` is handled" is not a claim anyone can make. So 2 of the
16 read fields are enumerable and the other 14 are listed in
`UNBOUNDED_FIELDS`, each with the reason enumeration does not apply, and
`unenumerated_read_fields()` fails if a read field appears in neither list.

Without that second check the whole thing would cover an eighth of the surface
and report itself complete — which is precisely the failure mode being fixed,
one level down. The reasons are not filler either:

    font_size   ordinal, 207 distinct pixel heights, consumed by RANK within a
                document (259). Enumerating them would invite exactly the
                absolute threshold that ranking exists to avoid.
    type        delegated — it is covered value-by-value by CLAIMED / IGNORED,
                which is what 250 already is.
    confidence  continuous, consumed by comparison.
