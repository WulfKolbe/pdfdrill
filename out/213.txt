SIX OF THE ELEVEN REPORTS MUST NOT BE MEASURED — WHICH IS 214's CONSTRAINT
------------------------------------------------------------------------------
Six reports carry GLYPHS DROPPED: xelatex discarded a character and STILL
WROTE A PDF, rc=0. Thirty-four characters lost across the six. The report
looks complete; the symbol is simply not on the page, with no visible trace.

That is exactly the failure class the ink residual cannot survive. The
residual compares rendered ink against scanned ink; a glyph missing from the
render is indistinguishable from a glyph the OCR never emitted. Measuring
these six would attribute a font gap to the extraction.

read the log and not just the return values.

0707.4470 — THE ADVICE THE WARNING GIVES IS WRONG FOR THIS ONE
------------------------------------------------------------------------------
Five of the six dropped an exotic code point: U+09E7 BENGALI DIGIT ONE,
U+53E3, U+5B5B, U+5B80 (CJK), U+53E3 again. For those the emitted advice —
"add the code point to report_tex._MATH_CMD or a fallback font" — is right.

0707.4470 dropped

   Missing character: There is no g ("67).

"67 is TeX's hex notation: 0x67, ASCII lowercase **g**. A plain Latin letter.
No fallback font is missing 'g'; a font that has been selected for some
symbol in that document has no 'g' in it, and a letter fell into it. Adding
'g' to a math-command table would be nonsense. The bug is the font selection,
not the coverage, and the warning text sends a reader to the wrong place.

Worth fixing in the message: when the dropped code point is below U+0080,
say so and name the font, because the diagnosis inverts.
