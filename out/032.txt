SEMANTICS CHOSEN, AND WHY
------------------------------------------------------------------------------
   --limit is REQUIRED and 0 MEANS ALL. The unbounded run stays reachable but
   has to be asked for in words. Removing it entirely would have made the
   full-corpus pass impossible; leaving it optional is what created the
   problem, since two harnesses advertised a limit whose default disabled it
   — worse than no flag at all, because it reads like a bound and is not one.

THE ANNOUNCEMENT
------------------------------------------------------------------------------
   Printed to stderr before the first document is touched, e.g.

       [make_libraryindex] planned: 2 document(s), 596 page(s)
       plan:   2 documents, 6 pages at 400 DPI          (corpus_pages, kept)

   Page counts come from the cheapest local source that knows: sidecar
   evidence, then lines.json, then pdfinfo. A document whose page count is
   NOT knowable locally — a drillbatch URL that has not been fetched yet — is
   reported as unknown rather than guessed:

       [drillbatch] planned: 12 document(s), 0 page(s)
                    (+12 document(s) whose page count is not knowable locally yet)

   A plan that invents its own size is worse than one that admits what it
   cannot see.

ONE PLACEMENT NOTE, STATED RATHER THAN HIDDEN
------------------------------------------------------------------------------
   In speak_library.py the announcement comes after the library SCAN that
   decides which documents need speech and orders them cheapest-first. On a
   3,363-document library that scan takes minutes, so the plan line is not
   instant there. Moving it earlier would have meant limiting before the
   sort, which silently changes which documents a bounded run selects — a
   worse trade than a late line. The scan predates this change.
