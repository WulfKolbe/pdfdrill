431 — `model --force` refuses over enrichments
==============================================

THE GUARD ALREADY EXISTED AND COVERED ONE CLASS

`model_rebuild_blocked` refuses a rebuild of a TRANSLATED model, and its
docstring records why: "Three times during one week of work that destroyed
the same document's translation, each time recovered only because a backup
happened to exist."

That lesson was learned three times and generalised to nothing. Every other
enrichment had the identical failure with no warning at all — while
`pdfdrill rename` refuses to rebuild for exactly this reason and says so in
its summary. Two commands, one destructive behaviour, one warning between
them.

THE MESSAGE, on 1510.06699 (nothing was written)

  Refusing to rebuild: this model carries enrichments the rebuild would
  destroy — 181 edit_source, 181 latex_prepunct, 1 latex_pretail,
  181 trailing_punct.
    The model is rebuilt from lines.json, which holds none of them, and a
    rebuild also REGENERATES OBJECT IDS: 0.0% survived on a measured document
    (1 of 2,196), so id-keyed sidecars and the semantic graph dangle too (430).
    • to change one thing without a rebuild, run the step that mutates in
      place (`eqnums`, `geometry`, `clean`)
    • to rebuild anyway, pass --force-discard-enrichments; the refinements are
      not recoverable from lines.json and would have to be re-proposed and
      re-verified (`pdfdrill refine`)

It names the counts, the reason, the in-place alternative, and the cost of
overriding. The id regeneration is in the message deliberately: it is the
part that reaches outside the model, and a reader deciding whether to pass
the flag cannot weigh it if only the props are listed.

A SECOND DEFECT, FOUND WHILE WIRING THE FIRST

`cmd_model` already took `force_discard_translation` — and `cli._do_model`
never passed it. The parameter existed, the refusal existed, and no CLI path
could get past it: the flag was a dead end rather than an override.

That is 400's shape exactly (`--no-legend` accepted by the CLI and absent
from the manifest), arriving from the opposite direction — present in the
signature, absent from the CLI. Both overrides are now wired, declared in
commands.yaml, and in `--help`.

CHECKED, and one thing deliberately not done

The guard fires only on `--force`, which is the destructive path. An ordinary
`pdfdrill model` on a document that already has one does not rebuild, so
nothing changes for it.

2,761 tests pass, 5 new — including one asserting a CLEAN model does not
refuse. A guard that fires on everything is one people learn to pass with a
flag, and then it protects nothing.
