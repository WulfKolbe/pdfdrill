128 — CJK / ideographic-description validator, corpus count
========================================================================
VALIDATOR  report_tex.cjk_defect(latex) -> reason or ""
Rejects a maths value containing any of:
  * U+2FF0–U+2FFB  Ideographic Description Characters
  * CJK ideographs U+3400–4DBF, 4E00–9FFF, F900–FAFF, and the SIP extensions
  * a \zh command (word-boundary matched, so \zhang is not a hit)
Wired into renderable(), so a contaminated value never reaches xelatex.

WHY THESE ARE ALWAYS A DEFECT IN MATHS
U+2FF0–U+2FFB are not glyphs. They are a notation for DESCRIBING how an unknown
ideograph is composed — "⿱ 日 一" means "the character with 日 above 一". Their
presence is MathPix reporting that it could not identify a character and
emitting the recipe instead. In a formula there is no reading under which that
is content.

SPECIFICITY — the check that decides whether this validator is safe
------------------------------------------------------------------------
A corpus this size (335,043 maths values) contains genuinely Chinese and
Japanese documents, and rejecting their mathematics would be a worse bug than
the one being fixed. Three documents carry real CJK PROSE:

    CN208060706U        5,698 prose ideographs   flagged maths values: 0
    DH2017-abstracts      257 prose ideographs   flagged maths values: 0
    2409.01704v1          192 prose ideographs   flagged maths values: 0

Zero. CJK appears in their paragraphs, where it belongs, and never inside a
maths value. So the validator separates the two populations cleanly on this
corpus, and the 26 hits are contamination rather than content.

The residual risk is a document that legitimately sets an ideograph INSIDE
mathematics (a Chinese textbook using 甲 as a variable). None exists here; if
one appears the validator will reject it, and the reason string names the exact
character so the case is diagnosable rather than mysterious.

EFFECT ON 0902.0431
------------------------------------------------------------------------
EQ1032 (page 173, confidence 0.022) carried ⿱ and was RENDERING — xelatex
dropped the glyph and wrote the PDF anyway. The build said so:

    GLYPHS DROPPED: xelatex discarded 1 character(s) and still wrote a PDF.
    Missing character: There is no ⿱ (U+2FF1).

After the validator that row is marked (not rendered) instead, and the report
compiles with zero dropped glyphs. The unrendered count goes 7 -> 8; that is not
a regression. A row that is visibly absent can be triaged. A row that renders
with a character silently missing cannot, and would be measured as if it were
correct.
