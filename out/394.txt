THREE DEFECTS IN THE RENAME PATH, found by auditing rather than by a test
------------------------------------------------------------------------

Nothing rebuilt, so none of these announced itself. The files simply sat
there being wrong, which is why the audit had to be done by hand.

1. report.regions.json WAS NOT IN THE RENAME PATH AT ALL.

   Its `bibkey` is a live identifier and its 116 row ids are the sanitized
   bibkey plus `_PIC_0001`. After the rename every id named a document that
   no longer exists while the report carried the new key, so the regions
   residual would join two populations that cannot intersect — 0 of 116 —
   and `residual_colour` renders that as a fully measured document in which
   nothing could be measured. report_tex.py:826 already warns about exactly
   this shape from the other side. Added `_retarget_regions`.

2. standalone-regions WAS NOT RENAMED.

   `rename_bibkey_files` covered report-crops and the OKF bundle, not this.
   Its 9 files kept the old name and report.tex still resolved them, so
   nothing broke and nothing said so: the old title, Z-Library marker and
   all, stayed on disk and in every \includegraphics path reaching the built
   PDF. Added, plus the matching path rewrite in report.tex.

3. NOT ONE OF 5,709 \ident{} SITES WAS RETARGETED, and the count said 411.

   This is the one worth reading. `rename_report_tex` matched the sanitized
   key with plain underscores; `\ident{}` content is written by
   `breakable_ident`, which escapes every underscore as `\_\allowbreak{}`.
   A comment in that function already recorded this failure once ("matched
   none of the 97 \ident{} sites on the first run") and the fix handled the
   separator AFTER the key but not the underscores INSIDE it.

   Two further pattern fixes each matched a little and missed most:

     as-is, with lookahead            0 of 5709
     trailing "_" stripped          158 of 5709
     unescape and compare          5709 of 5709

   The 158 was the trap. A pattern that matches some sites returns a nonzero
   count, and the command reported "411 report.tex references" the whole
   time — 411 crop paths, 0 identifiers. A count that is nonzero for the
   wrong reason reads exactly like success.

   The escaping is not describable by an underscore rule anyway:
   `breakable_ident` also breaks after a PERIOD, so the real text contains
   `etc.\allowbreak{}\_\allowbreak{}`. So the identifier is now UNESCAPED,
   compared plainly, and written back escaped. The rule depends on the key
   and on nothing else.
