WHICH FILE EACH GOT, ON THE NINE
---------------------------------
`next(d.glob(...))` is not sorted and not stable across documents. Before
the deletion it returned:

  the CURRENT bibkey file   cardona, fong-spivak-invitation,
                            fong-spivak-seven-sketches, kohlhase, voloshin
  the STALE folder file     gilmore-lie-groups, johnston-linear-matrix-
                            algebra, lyche-numerical-linear-algebra,
                            mielke-geometrodynamics

So four production consumers read a 1 September array on four documents —
`corrections.py` among them, which is the identifier join behind
corrections.html.

`sorted(glob)[0]` gets the stale file on ALL NINE, because the long folder
name sorts before the bibkey. That is the bug in my own 550 measurement,
which reported "the fix does nothing" for twelve documents.

`_resolve_tiddlers` was never affected: it reads
`sc.get_evidence("tiddlers_path")` first and every sidecar named the
current file. The `<pdf.stem>.tiddlers.json` fallback IS the stale name on
these nine, so it was one lost evidence key away from firing.
