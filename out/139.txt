2502.20855v2 — MY MEASUREMENT WAS WRONG, NOT THE MODEL
--------------------------------------------------------
Reported 501 changed. It is an artifact of the comparison key.

I aligned objects by (type, flow_index) because object ids are content-derived,
so a changed value changes its own id and an id diff would report every edit as
a delete plus an add. But flow_index is POSITION-derived: this rebuild produced
1741 -> 1747 objects (+6 non-maths), which renumbered everything after the
insertion point. The key then compared unrelated objects — the recorded sample
pairs `\frac{d}{dg(z)} f(g(z))...` against `z, y`.

What can still be said: the maths object COUNT is unchanged at 441, and this is
a MathPix model whose macro table is not consulted, so a macro-driven change is
not possible here. What cannot be said is whether any individual value changed:
the rebuild overwrote the before-model and I did not keep a copy of the values,
only the aligned digest. That is a gap in how I set the run up, and it is not
recoverable without rebuilding from a backup that does not exist.

A multiset diff of the LaTeX values would have been immune to both problems —
it needs neither stable ids nor stable positions — and is what this comparison
should have used.
