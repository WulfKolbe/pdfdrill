WHAT THE REJECTED ROWS SHOW THAT AN ACCEPTANCE-ONLY REPORT COULD NOT
------------------------------------------------------------------------------
Three rows got substantially WORSE and are visible as such: EQ0924 at +57,
EQ0335 at +46, EQ0547 at +6. A report listing the eight acceptances would
have shown eight repairs averaging -80 and looked like an unambiguous
success. It is one, but only because a gate stood between the model and the
model file — and the reader can see that only if the refusals are on the page.

Three more say "identical to the original": the model returned the input
unchanged, so there was nothing to measure. That is a distinct outcome from
"measured and no better", and collapsing them would overstate how often the
proposer engaged with the row at all.

THE ROW THAT PRODUCED NO MEASUREMENT — AND WHY IT IS NOW ON THE PAGE
------------------------------------------------------------------------------
   EQ0366   conf 0.3155   before 62   after —   NOT PROPOSED
            "reply empty: the model used all 40000 tokens reasoning and
             emitted no content"

Until this task that row was EXCLUDED. out/174 had reasoned that a row
selected and never proposed has no before/after to show, and a line of dashes
would read as a measurement that came out empty.

That reasoning was half right and the half it got wrong matters here. A row
that was never ATTEMPTED should stay out. A row that was attempted, cost a
paid call, and failed is a different thing: leaving it out makes the report
claim 18 repairs were tried when 19 were. So the rule is now the narrower one
— a row appears if it carries a propose_error, and its verdict is the error.
A row selected and never called still does not appear.

Two tests hold both halves apart.

A NOTE ON THE FILENAME
------------------------------------------------------------------------------
217 asks for report-refined.pdf; the file is refine.report.pdf. The name was
changed deliberately: `report.*` in a document folder sweeps twelve files,
including report.ink.json.MISPAIRED — a quarantined file whose whole purpose
is that it must never be republished. A refined report named report-refined.*
would sit in that namespace. The current name shares no prefix with anything
published, and the pages side has an allowlist that admits files by name.
