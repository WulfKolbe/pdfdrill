A. WHAT WAS ADDED

  meta['build']    written once, in docmodel.main.run, when the object graph
                   is constructed from lines.json. Never overwritten.
  meta['written']  written on every model_io.save_model. After an enrichment
                   pass this is not the code that built the structure.

Both are {sha, dirty, version, at}. `dirty` counts modifications to TRACKED
files only - an untracked scratch file does not change the behaviour of
imported code, and counting it would mark every build here dirty forever.
The stamp is cached per process, so a 21-document sweep shells out to git
once and every model in it carries the same sha.

B. THE GUARD

buildstamp.spread() groups documents by generation; guard_lines() is the
block a report prints when the spread is not one; require_one() raises for
code that must never emit a cross-generation number. Two rules that are not
obvious and are both tested:

  - an UNSTAMPED model is its own generation, never folded into the
    majority. Folding it in is precisely the silent averaging that produced
    574's 1458.
  - a clean tree and a dirty tree at the same sha are TWO generations. The
    sha names a commit whose code is not what ran.

`pdfdrill generations <pdf|dir|model> ... [--written]` reads it. It is in
the manifest (145 commands, typed), not in tools/, so the planner and
`status` can see it.
