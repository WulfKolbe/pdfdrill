THE RULE
--------
`<library>/out/<NNN>/INSPECT.txt` — one absolute path per line, nothing
else — plus the same list printed with a one-line reason per path.
`taskout.inspect_list` / `taskout.inspect_report`; HANDOVER-RULES rule 20.

The reasons are deliberately NOT in the file. drillui's scanner reads it;
the reasons belong in the printed block and in out/NNN.txt. "B.pdf — 10
pages of 233 rows, the layout under discussion" is worth more than the path
alone, and it is what these reports have been missing whenever they named a
file.

A PATH IN THAT FILE IS A PROMISE
---------------------------------
Every path is checked for existence AND non-zero size before it is written.
One that fails is not written — it is reported with the reason. 408: an
unreachable path is only half of reachable, and a list that quietly holds a
dead path is worse than a short list. Tested: an empty file and a missing
file are both refused, and the reason never leaks into the file.

WHAT IT DOES NOT SOLVE, NAMED
------------------------------
Roughly half this library's folder names contain spaces — "Geometric,
Algebraic and Topological Methods for Quantum Field Theory (Alexander
Cardona (ed.) etc.) (Z-Library)". Such a path is correct in a line-based
file, and drillui's scanner, which splits on whitespace, cannot open it.
`inspect_list` returns those under `whitespace` and the printed block says
how many. Two of 542's six are in that state. The fix belongs in the
scanner; dropping the paths would be losing evidence to protect a consumer.
