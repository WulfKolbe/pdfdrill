================================================================

WHERE THE LEAK LIVED (Before You Begin — which layer owns it)
  NOT already stripped at parse time. `pdfdrill.bibliography.parse_bibliography`
  recognised the printed label (`[N]`/`N.`/`N)`) to compute `number` (the
  `lead` regex, pre-existing) but stored the FULL joined line — label intact —
  into both `raw_text` AND, via `_author_block(text)`, into `author`. The
  `_bibitem` projector's fallback body is `"author (year) title"` when any of
  those is non-empty; the heuristic path always sets `author`+`year`, so the
  rendered body was `author` (still carrying "[1] ") + " (year)" — the exact
  string in the compiled PDF. The SAME `raw_text`/`author` also feed
  TiddlyWiki's `{{||CIT}} <raw_text>` line (`tiddlywiki.py:1408`), so the
  identical leak existed there too, undetected until now.
  FIX LOCATION: `parse_bibliography` in `src/pdfdrill/bibliography.py` — the
  one place that PARSES the label (rule: strip where you parse), not
  `bibliography_block`/`_bibitem` in `latex_pipeline.py`, which only
  re-prints what the parser decided and never re-derives a number itself.
  One fix now correctness-fixes both the LaTeX and the TiddlyWiki projections.

THE FIX
  `src/pdfdrill/bibliography.py::parse_bibliography` — `number` is computed
  from the leading-label match exactly as before, then a new
  `_strip_own_label(text, number)` drops that label from the text BEFORE
  `year`/`author`/`citekey` are derived from it, so `raw_text` and `author`
  both come out clean. `_strip_own_label` only strips when the matched
  digits equal the entry's OWN number; a leading bracket that names a
  DIFFERENT number is left untouched (`bibitem_label_mismatch` — tested
  directly, not reachable through the current parse flow since `number`
  and the label come from the same regex match, but kept as a guard against
  stripping the wrong text under a future caller).
  `src/docops/projectors/latex_pipeline.py::_sanitize_bib_body` (640-f) — now
  routes the body through `balance_math` (the same runaway-`\(`/`$` guard
  every OTHER prose block gets in `_prose`, `latex.py:770`) before
  `_balance_braces`. This was the one remaining Steerable compile error:
  `\bibitem{Unser16}`'s OCR'd body ends "...in \(L^" (an unclosed inline-math
  span) which swallowed the NEXT `\bibitem{Unser2008}` and TeX reported
  "Missing { inserted" there instead of at its real source.
