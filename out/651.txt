651 — `pdfdrill tiddlers --update <old.tiddlers.json>`
======================================================

WHAT CHANGED
  `pdfdrill tiddlers <pdf> --update <old.tiddlers.json>`: after projecting
  fresh (unchanged), merge an OLDER tiddler array onto it, matched BY TITLE
  (650's own result — a title survives a rebuild from lines.json unchanged —
  is the precondition this leans on; without it, matching by title would be
  matching two unrelated things).

  New in `src/docops/projectors/tiddlywiki.py`:
    KEEP_LIST            {field: KeepEntry(reason, predicate)} — ONE constant,
                         one argued comment per entry (below).
    _is_hand_edited      the predicate for the two conditional entries
                         (text/caption): a translation marker (`*_source` /
                         `translated_lang`, written only by
                         `_translate_tiddler_file_inplace`) or `modified` >
                         `created` in the OLD tiddler (a fresh projection
                         always stamps both identically — `_t()` — so any
                         daylight between them is real TiddlyWiki edit
                         history the model cannot have).
    _keep_old            field, old tiddler -> the reason OLD wins, or None.
    _dangling_targets    every `{{target}}`/`{{target||tpl}}` in a value
                         whose target isn't in the fresh title set.
    merge_updated_tiddlers(fresh, old) -> {merged, restored, unmatched,
                         unmatched_by_kind, refused_dangling, newly_orphaned}
                         — the whole rule, in one function; see below.
    keep_list_report()   printable keep-list lines, used by both the CLI
                         message and this file.

  New in `src/pdfdrill/commands.py`: `cmd_tiddlers(..., update=<path>)` —
  loads the old array, calls `merge_updated_tiddlers`, writes the merged
  array in place of the fresh one, and writes two records beside it:
    <bibkey>.update.json            old_file, keep_list (with reasons),
                                    keep_prefixes, restored, refused_dangling,
                                    unmatched, unmatched_by_kind, newly_orphaned
    <bibkey>.update-unmatched.json  the unmatched OLD titles, bare (a list)
  and appends a summary to the command's own return string: fields restored,
  titles unmatched (by kind), restorations refused (dangling), tiddlers newly
  unreferenced, and the keep-list itself (name + reason for every entry).

  CLI: `--update <path>` on `pdfdrill tiddlers` (`src/pdfdrill/cli.py`,
  `_do_tiddlers`). Manifest: `.claude/skills/pdfdrill/commands.yaml` gained
  the flag (type: path); `requires`/`done_when` unchanged (this is not a new
  layer, it is an option on an existing one — nothing new to reach). Synced:
  `python3 tools/skillsync.py all .` (SKILL.md, `_help_generated.txt`, the
  bundled skill copy).

THE RULE, PLAIN
  For each fresh tiddler matched by title:
    field in OLD, absent from fresh        -> restored unconditionally
                                              (the model has NOTHING to say —
                                              a paid/manual step, translate/
                                              refine/speak/trailingpunct, was
                                              never re-run after the model
                                              was rebuilt)
    field in BOTH, same value               -> no-op
    field in BOTH, different, NOT on
      KEEP_LIST (and no user_/note* prefix) -> the model's fresh value wins
    field in BOTH, different, ON KEEP_LIST
      (predicate passes, if any)            -> OLD wins
    a text/caption restoration (either path
      above) that would DANGLE              -> REFUSED; fresh value kept
                                              instead, counted in
                                              `refused_dangling`
  An OLD title with no match in fresh is never inserted (650: an unmatched
  title is stale, not merely renamed) — it is counted (`unmatched`,
  `unmatched_by_kind` via `parse_title`) and written to
  `<bibkey>.update-unmatched.json`, never silently dropped.

THE KEEP-LIST, ARGUED (also `keep_list_report()`, printed by the CLI itself)

  text          [conditional — OLD must show hand-work]
                Restoring `text` unconditionally would freeze every future
                OCR/transclusion fix onto every Paragraph/Footnote/Sidenote/
                Abstract tiddler forever — exactly the opposite of what 650
                bought (the projector rebuilds `text` deterministically from
                the model's OWN realization on every run; a stale hand
                value re-baked in stops that dead). So it is kept ONLY when
                OLD's own value is hand-work: a translation marker
                (`text_source`/`translated_lang`, from `pdfdrill translate`'s
                tiddler-level pass) or `modified` newer than `created` (a
                real wiki edit — `_t()` stamps both identically on every
                fresh build, so daylight between them is history no rebuild
                has).

  caption       [conditional — same predicate]
                Same rebuild-from-model path as `text`, for a Section's
                heading and for Picture/Diagram/Table's caption. The latter
                three are translated at the MODEL layer
                (`_TRANSLATE_MODEL_FIELD`, commands.py) with NO tiddler-level
                `caption_source` twin at all — see CONCERNS: for these three
                kinds, `modified` > `created` is the ONLY signal, and
                `pdfdrill translate` never touches `modified`.

  trailing_punct
                Moved out of `latex` by the SEPARATE `pdfdrill trailingpunct`
                command (025), never by `model`/`tiddlers`, and named in
                `commands.ENRICHMENT_MARKERS` (431) as an enrichment a model
                rebuild destroys. The projector emits it UNCONDITIONALLY —
                `e.props.get('trailing_punct', '')` — so a rebuilt model
                that has not re-run `trailingpunct` yet is "present in
                both" with an EMPTY fresh value, which would blank out a
                correct split rather than leave it alone if this were not
                kept. (The three siblings of this same ENRICHMENT_MARKERS
                entry — `latex_pretail`, `latex_prepunct`, `edit_source` —
                are NOT here: the projector never puts any of them onto a
                tiddler at all, grep-confirmed zero hits, so a tiddler-array
                merge has nothing to keep.)

  latex_refined, refined_basis, refined_verified_by, refined_author
                A VERIFIED refinement (`pdfdrill refine`; ink-gate- or
                LLM-proposed, human- or automated-verified) held on a TWIN
                prop precisely so `latex` itself is never overwritten
                (PROPS.md 232/233). Regenerating it means re-running the
                paid, separately-verified pipeline, not a `model`/
                `tiddlers` rebuild; once verified, a later unverified pass
                does not get to silently replace it. The three evidence
                fields are meaningless detached from `latex_refined` and
                are kept with it for the same reason.

  spoken        A TTS phonetic spelling (`pdfdrill speak`) a human can
                correct for a pronunciation the engine gets wrong. The
                engine cannot reproduce a person's correction, and the
                field is emitted only when non-empty, so this only ever
                fires on a genuine disagreement between two non-empty
                readings — never on a document that has simply never run
                `speak` (that case is the plain absent-rule instead).

  user_* / note*  [prefixes, not exact field names]
                Reserved wiki-author namespace. The projector has never
                written a field under either prefix (grep of its own key
                vocabulary) — this is currently redundant with the
                absent-rule (these fields are always "present in OLD,
                absent from fresh" today) but is written down as a promise:
                if the model ever grows a same-named field, the human's
                still wins, by convention, not by omission.

  DELIBERATELY NOT ON THE LIST, AND WHY (argued, not omitted):
    text_source / caption_source / content_source / translated_lang
      Never emitted by the projector itself (only by
      `_translate_tiddler_file_inplace`, a POST-process on the written
      array) — always "present in OLD, absent from fresh", so the baseline
      absent-rule restores them with no keep-list entry needed. An entry
      here would be vacuous.
    latex_pretail / latex_prepunct / edit_source
      Real `commands.ENRICHMENT_MARKERS` a model rebuild destroys, but
      never projected onto a tiddler at all (zero hits in tiddlywiki.py) —
      a tiddler-ARRAY merge cannot keep a field that was never a tiddler
      field. `trailing_punct`, the fourth marker in that same list, IS a
      tiddler field, and is kept (above).
    tags
      Deliberately excluded, not silent. The model recomputes tags fresh
      every run (kind/bibkey/tikz/stub tags describe the CURRENT object),
      and a hand-added tag — e.g. the `translated` marker
      `_translate_tiddler_file_inplace` adds — is lost on `--update` even
      when the SAME title also keeps `text`/`caption`. That restores the
      CONTENT, not the filter tag naming it. See CONCERNS.
    latex, displayMode, canonical_uri, page, confidence, mathpix_text, …
      Everything else the projector writes is a pure, deterministic
      function of the CURRENT model with no separate human/paid decision
      recorded anywhere else — the brief's own worked example (`latex`):
      the model wins, always. (A verified correction to `latex` has its
      OWN twin field, `latex_refined`, precisely so `latex` never needs
      this kind of protection — PROPS.md 232.)

THE OTHER COUNT — `newly_orphaned` (not asked for verbatim, found doing the
evidence run; the brief's own hint: "consider whether there are others")
  `refused_dangling` guards one direction: a restored `text`/`caption`
  pointing at a target that no longer exists. The OTHER direction is
  symmetric and just as silent if uncounted: a restored `text`/`caption`
  that simply DROPS a `{{...}}` marker the FRESH prose still carried,
  orphaning a tiddler that was reachable a moment ago. This is not refused
  (the field is still hand-work and still wins — dropping content is not
  the same defect as a broken pointer) but it IS counted:
  `merge_updated_tiddlers` diffs `tiddler_integrity(...)["unreferenced"]`
  before and after the merge and returns the new titles under
  `newly_orphaned`; `cmd_tiddlers` surfaces it in the CLI note and in
  `<bibkey>.update.json`. Measured live on penev_A below — this is not a
  hypothetical.

CONCERNS
  1. Picture/Diagram/Table `caption` translation has NO tiddler-level
     marker at all (translated at the MODEL layer only, before the first
     projection — no `caption_source` twin is ever written to the tiddler).
     `modified` > `created` is the ONLY signal `_is_hand_edited` has for
     these three kinds, and `pdfdrill translate` never touches `modified`
     on ANY tiddler (checked: `_translate_tiddler_file_inplace` sets
     `text`/`caption`, the `_source` backup, `tags`, `translated_lang` — not
     `modified`). So a translated Picture/Diagram/Table caption surviving a
     `model --force` (the exact scenario 650's own refusal gate exists to
     protect against, when overridden with `--force-discard-translation`)
     is NOT reliably protected by this merge unless a human ALSO opens and
     re-saves the tiddler in TiddlyWiki itself afterward. Named, not fixed:
     out of this task's own corpus (penev_A/Steerable carry no such
     translated caption to measure against) and would need either a
     tiddler-level `caption_source` write at translate time (a change to
     `cmd_translate`, not to `--update`) or accepting the gap.
  2. `tags` are never merged. A hand-added tag (most notably the
     `translated` marker `_translate_tiddler_file_inplace` writes) is lost
     on `--update` even on a title whose `text`/`caption` IS correctly
     restored — the wiki stops FLAGGING the tiddler as translated even
     though it still reads as translated. Deliberately out of scope (the
     brief asked for a field keep-list, and `tags` mixes structural,
     freshly-recomputed information with occasional hand additions in one
     string) but worth a reader's attention before assuming tag-based
     filtering survives an `--update`.
  3. `newly_orphaned` is INFORMATIONAL, not a refusal — unlike
     `refused_dangling`, nothing here stops the hand-work from winning even
     when it demonstrably drops a reachable citation/footnote. That is the
     correct call (a translator's own retyped paragraph choosing to drop a
     parenthetical citation is a legitimate editorial decision, not a bug),
     but it means a large or careless hand-edit could silently thin out a
     document's reachability graph one `--update` at a time if nobody reads
     the count. `pdfdrill conserve` (the wider "is every object reachable"
     question) is the standing check for that; this task only makes the
     PER-RUN delta visible, the same posture 650 took with
     `footnote_not_narrowed`.
  4. `--update` is matched by EXACT title only, per the brief. A document
     whose bibkey changed between the two files (a `--bibkey` override
     between builds) will match NOTHING and report every old title as
     unmatched — correct per the rule (a title is bibkey-qualified,
     `<bibkey>_PREFIX...`), but worth knowing before assuming a large
     unmatched count means something is broken rather than a bibkey
     mismatch.

CONCERNS (fix round 1: item 5 replaces the original evidence framing;
items 1-4 unchanged, still accurate per the review)
  1. Picture/Diagram/Table `caption` translation has NO tiddler-level
     marker at all (translated at the MODEL layer only, before the first
     projection — no `caption_source` twin is ever written to the tiddler).
     `modified` > `created` is the ONLY signal `_is_hand_edited` has for
     these three kinds, and `pdfdrill translate` never touches `modified`
     on ANY tiddler (checked: `_translate_tiddler_file_inplace` sets
     `text`/`caption`, the `_source` backup, `tags`, `translated_lang` — not
     `modified`). So a translated Picture/Diagram/Table caption surviving a
     `model --force` (the exact scenario 650's own refusal gate exists to
     protect against, when overridden with `--force-discard-translation`)
     is NOT reliably protected by this merge unless a human ALSO opens and
     re-saves the tiddler in TiddlyWiki itself afterward. Named, not fixed:
     out of this task's own corpus (penev_A/Steerable carry no such
     translated caption to measure against) and would need either a
     tiddler-level `caption_source` write at translate time (a change to
     `cmd_translate`, not to `--update`) or accepting the gap.
  2. `tags` are never merged. A hand-added tag (most notably the
     `translated` marker `_translate_tiddler_file_inplace` writes) is lost
     on `--update` even on a title whose `text`/`caption` IS correctly
     restored — the wiki stops FLAGGING the tiddler as translated even
     though it still reads as translated. Deliberately out of scope (the
     brief asked for a field keep-list, and `tags` mixes structural,
     freshly-recomputed information with occasional hand additions in one
     string) but worth a reader's attention before assuming tag-based
     filtering survives an `--update`.
  3. `newly_orphaned` is INFORMATIONAL, not a refusal — unlike
     `refused_dangling`, nothing here stops the hand-work from winning even
     when it demonstrably drops a reachable citation/footnote. That is the
     correct call (a translator's own retyped paragraph choosing to drop a
     parenthetical citation is a legitimate editorial decision, not a bug),
     but it means a large or careless hand-edit could silently thin out a
     document's reachability graph one `--update` at a time if nobody reads
     the count. `pdfdrill conserve` (the wider "is every object reachable"
     question) is the standing check for that; this task only makes the
     PER-RUN delta visible, the same posture 650 took with
     `footnote_not_narrowed`.
  4. `--update` is matched by EXACT title only, per the brief. A document
     whose bibkey changed between the two files (a `--bibkey` override
     between builds) will match NOTHING and report every old title as
     unmatched — correct per the rule (a title is bibkey-qualified,
     `<bibkey>_PREFIX...`), but worth knowing before assuming a large
     unmatched count means something is broken rather than a bibkey
     mismatch.
  5. (fix round 1, replaces the original "0 unmatched confirms 650"
     framing the review correctly rejected) A bare wiki hand-edit with NO
     `_source` backup carries no baseline at all -- `modified` > `created`
     is the only signal for it, and there is nothing recorded to compare
     against if the underlying model content moves between the OLD build
     and the FRESH one. `_stale_base_conflict` guards the translation path
     (finding 2's fix) but CANNOT guard this one: it is not a missing
     feature, it is a missing fact -- the OLD file itself never captured
     what the text looked like pre-edit. A future round could close this
     only by having the projector itself stamp a content fingerprint
     (e.g. a hash of the realization's own span) onto every prose tiddler,
     which is a change to the PROJECTOR, not to `--update`.
