THREE DEFECTS THE REBUILD FOUND, AND ONE OF THEM WAS MINE
----------------------------------------------------------
Committed separately (c0a5bcd) before the run that produced the table above.
None of the three would have failed a test; each produced a plausible
artefact.

  1. THE RESUME ASKED AN MTIME QUESTION. `fresh_ink` compared
     report.ink.json's mtime with the measure stamp's. `--profile published`
     drops the formulas section, so penev_B went 20 pages -> 11, and the
     stored measurement of the 20-page build still post-dated its own stamp.
     The resume fired, steps 2-4 were skipped, and the reading build adopted
     a residual measured on a document that no longer exists. It reported
     READY. Eleven of twelve documents did this before it was caught.

     It now asks four content questions: the ink post-dates the stamp; the
     ink's `measured_against` IS that build; the same formula rule; the same
     model. Caught because a document with an 878-second plan finished in 3.

  2. `build_report` TOOK THE BIBKEY FROM THE TIDDLERS FILENAME. 404 learned
     this for `publish_ready` and there is a test named for it; the same
     inference sat here unexamined. 462 renamed nine bibkeys and not their
     folders, so every title became `voloshin-hypergraph_EQ0001` while the
     file stayed `Introduction to Graph and Hypergraph Theory (…)`.
     `rows_for` matched nothing and built a ONE-PAGE report with no rows from
     a model holding 2,555 formulas and 266 equations. It compiled. It
     stamped. Nine documents.

     `resolve_bibkey` now reads `meta.bibkey`, and an empty report from a
     projection carrying typed titles raises `ReportRefused`.

  3. MY OWN NOTE BECAME A BRANCH. I added a "NO RESUME: … Re-measuring."
     line as an `elif`, and the `else` holding steps 2-4 bound to it — so
     every document with an existing ink.json printed the message and then
     measured nothing. The message caused the failure it exists to report.
     Caught because a run that should have taken fifteen minutes took forty
     seconds and printed no step 2, 3 or 4.

  19 tests across the three. 2,852 passing at the time of the run.

A FOURTH THING, WHICH IS OPERATIONAL AND NOT A CODE DEFECT
-----------------------------------------------------------
After defect 2 had emptied nine reports, `inkreport` refused all nine at
preflight — "equations table: 0 rows" — reading the manifest those empty
builds had written. The build that would repair the manifest was the one
being gated. The run does one `reporttex` first where the manifest reads 0
rows, which is step 2 of inkreport anyway. Worth knowing that the preflight
can deadlock on its own output; not worth changing the preflight, whose job
is exactly to refuse a report in that state.
