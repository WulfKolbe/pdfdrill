THE ROUTE IS A CHECK, NOT A FLAG
------------------------------------------------------------------------------
The ink gate cannot reach this row: an inline formula has no region and no
crop (out/125), so there is nothing to render a proposal against. What
0707.4470 does have is an arXiv e-print.

The obvious implementation — trust `basis: eprint` and record it — would have
made the whole loop bypassable by asserting a word. Instead the gate goes to
the author's source itself:

   1. take the object's surrounding PROSE from the flow text that carries it
      inline (an inline formula is written into its paragraph's text; nothing
      else in the model has its context);
   2. strip every math span from both sides and reduce to alphabetic words —
      the author writes `$1$-form` where MathPix writes `1-form`, so digits and
      punctuation disagree at every site and prove nothing, while the prose
      around the mathematics is written identically by both;
   3. locate that word sequence in the author source. ONE occurrence or the
      site is refused as ambiguous — a coin toss here is the defect the loop
      exists to stop;
   4. read the math span that sits there, and check the prose AFTER it agrees
      too;
   5. accept only if the value the source yields equals the value proposed.

For this row the before-context occurs exactly once and the span it points at
is `$\mathcal{J}$`. The proposal was not believed; it was re-derived.

NEVER THE .tex.zip
------------------------------------------------------------------------------
`author_eprint` reads `<stem>.tgz` only. The `<stem>.tex.zip` sitting in the
same directory is MATHPIX's own LaTeX output — out/229 nearly used it as gold
and it agreed with the markdown perfectly, because it IS the markdown
(\mathscr{g} present, counts identical). A verification that reads the thing it
is verifying confirms anything you like. A test holds this shut.
