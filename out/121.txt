TRANSPORT — why this run is comparable and the previous one was not
------------------------------------------------------------------------------
   The previous 121 run recorded six NetworkBlocked failures in E and then
   reported 'C and E are indistinguishable' from a column missing a third of
   its data. A comparison whose two columns have different n is not a
   comparison.

   This run hit the same class of failure — four consecutive HTTP 429
   'server overload' replies — and was STOPPED rather than allowed to
   complete. The runner now retries transient failures with exponential
   backoff (5s doubling to 80s, 5 attempts), spaces calls at 4s, and resumes
   from partial results so a retry never re-pays for a scored call.

   The retry predicate itself had to be corrected mid-run: it first covered
   only HTTP 429 and re-raised everything else, which immediately discarded a
   NetworkBlocked. The host answered HTTP 200 three times seconds later, so
   that failure was transient too. It now covers 429/overload/NetworkBlocked/
   unreachable/connection/timeout/502/503/504, while a genuinely unexpected
   error still raises rather than being silently retried.
