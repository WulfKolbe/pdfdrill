065 - source provenance is asserted before any author comparison
==============================================================================

ANSWER
------------------------------------------------------------------------------
   ALL 20 of the 20 documents would be refused.

   Every one carries a <stem>.tex.zip whose only .tex is named by that
   document's own MathPix image_id. Comparing against any of them compares
   MathPix with itself.

   20 of 20 also carry the author's e-print .tgz, and NONE of those is
   misclassified - so the check has a positive class of 20 and a negative
   control of 20, with no false positive on a real e-print.

WHAT WAS ACTUALLY USED - THE DAMAGE IS POTENTIAL, NOT REALISED
------------------------------------------------------------------------------
   'Would be refused' is not 'was wrong'. The sidecar records which source
   won for each document, and for all 20 it is:

       20  arxiv-eprint (author .tgz)

   cmd_injectlatex already PREFERRED the e-print, and that preference held
   everywhere in this population. No existing comparison in 040/057/059 is
   contaminated. What was missing is a floor under the preference: the
   selection chain FALLS BACK to the .tex.zip when no e-print is present,
   so a document whose source was never fetched would silently acquire
   MathPix output as its gold reference and every downstream comparison
   would read as agreement.

   That is the failure this closes. It is a guard on the fallback, not a
   repair of past results, and saying otherwise would overstate it.

THE TEST IS IDENTITY, NOT SHAPE
------------------------------------------------------------------------------
   mathpix  a .tex whose stem is one of THIS document's image_ids, read
            from its lines.json. Identity - not inference. Refused.
   suspect  a .tex named by a bare UUID that is not an image_id of this
            document. REPORTED, never refused: rejecting on shape alone
            would reject an author who happens to name a file that way.
   author   nothing indicates MathPix authorship. That is absence of
            evidence, and the code says so rather than promising gold.

   The .tgz files above are accepted under that third heading. A gzipped
   single .tex exposes no member name to test, so 'author' there means
   'nothing incriminating', not 'verified as the author's'.

WHERE IT FIRES
------------------------------------------------------------------------------
   In cmd_injectlatex, AFTER the source is chosen and before it is read -
   so it covers every route to a source: the preference chain, a path
   remembered from an earlier --tex, and an explicit --tex on this run. A
   check that only guarded the fallback would miss an operator pointing
   --tex straight at the .tex.zip, which is the easiest way to make this
   mistake by hand.

   The refusal is a typed MathPixSourceRefused carrying path, reason and
   remedy, in the shape net.NetworkBlocked uses: named and specific, never
   a stack trace. The CLI turns it into one sentence naming the file, why
   it was rejected, and the exact alternative to fetch.

   Accepting also records what was checked - sidecar evidence
   `latex_source_checked` - so a later reader can see WHICH test passed
   rather than only that something did.
