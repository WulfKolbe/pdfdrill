HOW THE MOVE WAS PROVED HARMLESS
--------------------------------
Every value was hashed BEFORE the move. After it, all 19 load byte-identical
to what Python held, and those 19 hashes are pinned in tests/test_prompts.py.
A move that dropped a newline, changed an escape or truncated at a quote fails
there. A deliberate prompt change now has to update the hash in the same
commit as the file — which is the point.

THE CONVENTION
--------------
  docs/prompts/YYYY-MM-DD-<name>-prompt.md

The date is when the prompt was WRITTEN, taken from the first commit touching
its defining file, not the day it was moved. Everything below the first line
that is exactly `---` is the prompt; the prose above it is provenance and
reaches no model. A file with no separator is entirely body, which is how the
existing task prompt already works and how docs/PROMPT_FOR_CLAUDE_AI.md
already separates the two.

THE HASH IS OF THE BODY, NOT THE FILE. Editing a provenance header must not
read as "the prompt changed". Tested both ways.

Found in order: $PDFDRILL_PROMPTS, then <repo>/docs/prompts/, then the bundled
copy in the package. There is deliberately NO fallback to an embedded string:
`prompts.load` on a missing name raises and names every directory it looked
in. A run that silently used a different prompt is what this exists to
prevent.

`tools/promptsync.py bundle` copies canonical to `src/pdfdrill/prompts_data/`
(declared package-data), and a test fails on drift — the arrangement `skill/`
already uses, for the reason the pyproject comment beside `scandrill.toml`
already gives: an installed wheel has no project root to search upward to.
