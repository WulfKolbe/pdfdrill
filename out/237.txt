WHAT THE ZIP IS MISALIGNED BY, EXACTLY
------------------------------------------------------------------------------
The TSV carries NO identifiers — report_page, line, dis, A_eq_B and the two
five-tuples, nothing else — so pairing can only be positional against
report.tex. And the TSV contains one all-zero row per page: the legend footer,
whose Rendered and Scan cells are blank because the legend spans all columns
via \multicolumn.

   all-zero rows == display pages == last row of every page:  1232 / 1232 / 1232

   and for every document:  tsv rows - all-zero rows == EQ identifiers
   in aggregate:            8,032 - 1,232 = 6,800 = out/213's equation total

So a naive zip pairs identifier i with row i while ~15% of the rows are
footers, and every identifier after the first footer takes another equation's
measurement. Drop the all-zero rows and the counts match to the row, in all
eleven — which is a post-condition worth asserting rather than trusting.

S IS UNREACHABLE FROM THIS FORMAT, WHICH IS WHY IT HAS NEVER BEEN SEEN
------------------------------------------------------------------------------
flag_of returns "stable" only when distance exceeds the noise floor, the
component delta is within it, AND scale_stable is true. The TSV has fourteen
columns and none of them is scale_stable — L_stk/R_stk are the stacked counts
inside the five-tuple, and A_eq_B is just (dis == 0). So the flag can only ever
be computed with stable=False, and every such row becomes W.

That is the mechanism behind the zero occurrences of S in 6,207 measured rows.
Not an unfalsifiable legend entry; a branch that this input format cannot
reach. The legend names five classes and the pipeline can produce four.
