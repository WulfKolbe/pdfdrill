FIX ROUND 1 — THE MIS-WIRE, THE RECIPE, AND THE PROOF
  1. CRITICAL, and it is the same class as the bug this task exists to fix.
     `LaTeXProjector._prose` ran `_pipe.resolve_citations(text, self._ref_map)`
     AFTER `_cite`/`_mark_footnotes`. That pass rewrites any surviving
     `[N]`/`[N,M]` bracket through `{Reference.number: citekey}` and has no idea
     which Citation owns the bracket. So the "only where a Reference exists"
     decision was UNDONE one step downstream: a Citation `NoSuchKey` over `[5]`,
     left verbatim and counted, became `\cite{Realname2001}` because an
     unrelated filled Reference was numbered 5. Not a dangling key — a SILENT
     MIS-WIRE that compiles clean and cites the wrong paper, which is worse than
     the bold `?` the task set out to remove.

     ONE RESOLVER OWNS CITATIONS. The numeric fallback moved INTO
     `projectors.citations` (`_numeric_fallback`, `numeric_brackets_resolved`)
     behind two guards:
       * a bracket that overlaps ANY Citation span is never touched — and a
         Citation claims its bracket whatever was decided about it, so a
         citation left verbatim protects its own text (`claimed_by_line` is
         built from EVERY Citation span, `spans_by_line` only from the resolved
         ones);
       * every number in the bracket must be a Reference, or it is an array
         index / an interval and stays raw (the old pass's own rule, kept).
     `_prose` gained `numeric_cites: bool = True` and the two callers the
     resolver owns (Paragraph/Abstract, ListItem) pass False. The old pass still
     runs where the resolver does NOT reach — a Footnote body, a beamer Abstract
     — so nothing was dropped.

     THE FALLBACK'S LEGITIMATE CASE IS KEPT AND TESTED: a bare `[5]` that no
     Citation covers, with a Reference numbered 5, still becomes
     `\cite{Realname2001}`.

     On penev_A and penev_B `numeric_brackets_resolved` is **0** and no number
     in this report moves: every Reference on both documents is a 010 stub and a
     stub carries no `number`, so `reference_map` is empty and the fallback
     cannot fire. The defect was reachable only on a document with numbered
     References — which is precisely why it needed a fixture and not a corpus.
