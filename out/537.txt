WHAT RECOVERS IT — MEASURED, NOT GUESSED
-----------------------------------------
Crops are written at the region's MathPix pixel size (~2067 px per page
width, so roughly 250 dpi) at JPEG quality 92. Re-encoded over a 120-crop
sample:

  setting                    of today   -> 21-doc total   johnston
  today: region px, q92          100%        707 MB        102.5 MB
  q75, full size                  62%        439 MB         63.6 MB
  q60, full size                  50%        354 MB         51.3 MB
  q75, 70% linear                 37%        262 MB         37.9 MB
  q60, 60% linear                 26%        184 MB         26.6 MB
  q50, 50% linear                 18%        127 MB         18.5 MB

**Recommendation: q75 at 70% linear.** 262 MB for the set, johnston at
38 MB, site total 1.04 GB. 70% of ~250 dpi is ~175 dpi, which is well
above what a line of prose needs to be read on screen — the evidence
surface needs the crop legible, not archival, and 461's pixel-exactness
requirement is about the SIZING computation (px2mm), which is preserved as
long as `crop_cell` is told the size the image was resized to.

If 1.04 GB is still too close, q60 at 60% gives 184 MB and a 960 MB site.

LINKING RATHER THAN EMBEDDING IS NOT AVAILABLE
-----------------------------------------------
A PDF cannot reference an external image; the bytes are in the file or the
picture is not there. That option exists only for the HTML surfaces, and B
is LaTeX for the reasons 530 measured. So the lever is dpi and quality.

NOT DONE
--------
Nothing re-encoded and nothing rebuilt. The eleven B files already built
also carry 535's wrong join, so the re-encode and the rebuild are one
operation, and it should be one decision: which of the two settings above.
