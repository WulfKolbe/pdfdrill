WHERE THE FLAG LIVES
--------------------
`env_mismatch` on the Equation/Formula object, set at model-build time
(src/pdfdrill/env_balance.py, called from cmd_model beside the existing
heading-cleanup pass). Idempotent, and a value that is later corrected LOSES
the flag rather than keeping a stale one.

It is diagnostic only — nothing gates on it. A value that renders correctly
after repair is not a rendering problem; it is an input-quality signal about
the OCR, and it belongs where input quality is read.

The corpus figures above come from applying the same detector to every model on
disk. The flags themselves are written when a model is next built: 0902.0431
was rebuilt for this task and carries them now; the other 92 documents will
carry them on their next `pdfdrill model`.

Counts, not set membership: `array` opened once and closed twice is unbalanced
even though the name appears on both sides. A set-difference check calls that
clean, and it is the shape a hand-rolled version gets wrong.
