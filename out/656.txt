656 — conserve becomes a gate
==============================

"make conserve a gate." The user stated an architectural invariant from
memory — "all non-textual objects should be transcluded and all output
should always be a projection" — and a transclusion audit found seven
object types that never reach the output, and found that `docops.conserve`
already detects every one of them but nothing runs it. The user chose to
close the INSTRUMENT half of the gap first. This task does NOT make the
seven types reachable — that is a separate task and is not touched here.

WHAT WAS BUILT
  src/docops/conserve.py
    BY_DESIGN         type -> the verified route its content actually takes
                      (the reachability-side twin of `CONTAINER_TYPES`,
                      held to the same standard — CONTAINER_TYPES' own
                      docstring: "an exclusion asserting a shape that does
                      not exist is worse than no exclusion"). Five entries:
                      Page, TableCell, TableRow, Toc (as already documented
                      for the anchors side / dead-Toc-emission) plus a NEW
                      one this task's measurement justified: Document (see
                      FINDINGS below).
    OUT_OF_SCOPE      type -> why this gate does not ratchet it: a WORKING
                      transclusion path (measured well under 100%
                      corpus-wide) whose nonzero count is the incidental,
                      already-catalogued class from 645/646's own
                      follow-ups (orphan paragraphs/sections, footnote
                      bodies whose inline substitution never runs, dark TOC
                      regions, lost citation-stub links) — not a missing
                      code path, and not this task's job. 13 entries:
                      Formula, Paragraph, Equation, ListItem, Reference,
                      Diagram, Sidenote, Footnote, Section, Table, Picture,
                      Abstract, LtxCommand.
    classify_unreachable(reach)   partitions `reachability()`'s
                      `unreachable` list into by_design / out_of_scope /
                      violations, per type. Neither of `conserve()`'s three
                      headline counts changes.
    load_baseline()   reads `conserve_baseline.json` (DATA, not code) —
                      `{}` if missing (an unaudited document gets ZERO
                      TOLERANCE, not a silent pass).
    gate(doc, res=None, baseline=None)   THE RATCHET. Every unreachable
                      object is by_design, out_of_scope, or a VIOLATION
                      whose count for this bibkey must match the baseline
                      EXACTLY: `new_types` (no baseline row for it),
                      `increased` (more than baseline — a regression),
                      `decreased` (fewer, INCLUDING ZERO — a stale
                      baseline, reported as a FAIL so it cannot be
                      silently accepted), `matched` (exact). `passed` iff
                      new_types/increased/decreased are all empty.
    format_gate_report(g)   verdict, then every FAIL reason (new/
                      increased/decreased, worst first), THEN the quiet
                      classes (matched, by_design, out_of_scope) — real
                      violations before housekeeping.
  src/docops/conserve_baseline.json   NEW. The committed ratchet, DATA:
                      penev_A, penev_B, 1811.06102, narcissus,

WHERE THE GATE LIVES, AND WHY
  `conserve` itself, not a new verb (CLAUDE.md: "a new capability is a
  layer in the manifest, not a new verb — and not a tool"). `--gate` is a
  flag on the existing, already-manifest-registered `conserve` command;
  `requires: [model]` was already correct and needed no change. The
  enforcement mechanism is `raise SystemExit(1)` inside the command
  function — the one precedent this codebase already has for a CLI check
  that fails a build (`skill_cmd.run`'s `--check`, used by
  `.github/workflows/skill-sync.yml`). `conserve` stays read-only by
  construction (no `@_writes`, no sidecar fact, no artefact) even in
  `--gate` mode: it still fixes nothing, it just now REFUSES to say nothing
  went wrong when something did. The classification (BY_DESIGN /
  OUT_OF_SCOPE) lives in code, reviewed like code; the baseline (per-
  document counts) lives in `conserve_baseline.json`, DATA, reviewed as a
  diff of numbers — the same split `docmodel.type_contract`'s
  CLAIMED/IGNORED-vs-`corpus_types.json` already uses for exactly this
  reason.

FINDINGS BEYOND THE AUDIT'S LIST (both new, both measured corpus-wide,
neither invented for this task)

  1. CITATION IS A NINTH VIOLATION, not a violation the audit weighed and
     dismissed but one it never measured corpus-wide. `Citation` has NO
     row in `TITLE_SHAPES` at all (grepped, HEAD) — the identical
     mechanism as Algorithm/Link/List/MathTail/AlgorithmStep, not the
     "marker rewritten to a REF transclusion" story the audit's Q1
     section called "arguably correct by design" and explicitly declined
     to resolve. Measured: 81,841 of 81,841 Citation objects, 100.0%,
     across 581 documents — the same 100%-or-nothing signature as the
     eight structural types. It is now a ratcheted VIOLATION type, not
     BY_DESIGN: the route the audit floated (the citing prose is replaced
     by a `{{REF||CIT}}` link, so the READER sees something, but the
     Citation object's own printed text is REPLACED, not carried) was
     never substantiated, and CONTAINER_TYPES' own rule says an
     unsubstantiated exclusion is worse than none.
  2. DOCUMENT IS A FIFTH BY_DESIGN TYPE. The model's own `Document`
     DocObject (`docmodel/modules/document_structure.py`'s
     `_create_document_root`, id=bibkey) reads 100.0% unreachable — 1,358
     of 1,358, one per document, in EVERY document that has one. Verified,
     not assumed: its own fields (`total_pages`/`total_sections`/
     `total_paragraphs`/`first_section_id`) are corpus-confirmed UNREAD
     (`docmodel.prop_contract.NO_READER_REASON`: "consumers walk the flow
     instead"/"count the objects instead"), and its one structural role —
     listing every top-level section — is independently duplicated by the
     PROJECTOR'S OWN root tiddler (`tiddlywiki.py`, title=bibkey, built
     from `doc.meta` + a fresh query over `Section` objects, never from
     this DocObject) — which is itself one of `reachability`'s two ROOTS.
     A second root already carries everything this object would.

CONCERNS
  The committed `conserve_baseline.json` covers seven documents, not the
  1,362-document corpus. That is a deliberate scope decision (stated
  above under WHAT WAS BUILT), not an oversight: the full corpus lives in
  a private, deny-by-default library that this repo's tests and CI cannot
  see, so a baseline entry for a document nobody running this repo can
  open would be untestable data. `pdfdrill conserve <pdf> --gate` on any
  OTHER real document gets zero tolerance (an empty baseline row) until
  someone adds one — which is the same posture `type_contract` already
  takes with an unclaimed corpus type, not a new one invented here.
  OUT_OF_SCOPE's 13 entries share ONE reason string rather than 13
  individually-cited ones: each type's nonzero count IS the class named
  (an orphan paragraph/section outside the reachable tree, a footnote/
  sidenote/list-item body whose marker substitution never ran, a dark TOC
  region, a lost citation-stub link — all four mechanisms are documented,
  by name, in 645/646's own follow-up lists), but this task did not
  re-verify, type by type, which specific mechanism accounts for which
  document's count. That re-verification is exactly the "make the seven
  types reachable" work the brief says is a separate task — extended here
  to "diagnose the thirteen out-of-scope types' own gaps," which is a
  different, larger task again.
  `1511.08771` (4.96 GB model) was excluded from the corpus measurement
  entirely — the population is 1,362 of the 1,363 models this library
  currently holds, not 1,363. Its own reachability is unmeasured by this
  task.
  The gate was verified against real documents by calling
  `docops.conserve.gate`/`conserve` directly (as `cmd_conserve` itself
  does internally) rather than by invoking the `pdfdrill conserve --gate`
  CLI entry point on penev_A / SteerableWaveletFramesBasedontheRieszTransform:
  the CLI path calls `_stale_or_absent` first, and running it against
  live, valuable library documents risked triggering an unwanted
  `cmd_model` rebuild pass. The CLI wrapper itself (the `--gate` flag
  parsing, the SystemExit/print contract) is exercised in
  `tests/test_cmd_conserve_gate.py` against a small synthetic model on
  disk instead.
