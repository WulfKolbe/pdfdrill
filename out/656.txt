WHERE THE GATE LIVES, AND WHY
  `conserve` itself, not a new verb (CLAUDE.md: "a new capability is a
  layer in the manifest, not a new verb — and not a tool"). `--gate` is a
  flag on the existing, already-manifest-registered `conserve` command;
  `requires: [model]` was already correct and needed no change. The
  enforcement mechanism is `raise SystemExit(1)` inside the command
  function — the one precedent this codebase already has for a CLI check
  that fails a build (`skill_cmd.run`'s `--check`, used by
  `.github/workflows/skill-sync.yml`). `conserve` stays read-only by
  construction (no `@_writes`, no sidecar fact, no artefact) even in
  `--gate` mode: it still fixes nothing, it just now REFUSES to say nothing
  went wrong when something did. The classification (BY_DESIGN /
  OUT_OF_SCOPE) lives in code, reviewed like code; the baseline (per-
  document counts) lives in `conserve_baseline.json`, DATA, reviewed as a
  diff of numbers — the same split `docmodel.type_contract`'s
  CLAIMED/IGNORED-vs-`corpus_types.json` already uses for exactly this
  reason.

  THE PROOF IS THE ROUTE, NOT THE PERCENTAGE (fix round 1 — a review
  correctly flagged the first draft of this passage for making the
  discriminator sound like a number). Each BY_DESIGN entry's classification
  rests on a separately verified code route named in `conserve.py:149-187`
  (`BY_DESIGN`; the review's own citation, `:197-235`, is off by the width
  of the comment block above it, not a different claim):
  Page has no `TEMPLATES`/`BLOCK_TEMPLATE` entry to render into at all;
  TableCell/TableRow fold into the parent Table's `raw_text`
  (`table.py:61`); Toc is deliberately never emitted, its outline REBUILT
  as the `<bibkey>_TOC` index instead (262); Document's own fields are
  corpus-confirmed unread and its structural role is independently
  recomputed by the projector's own root tiddler, never by reading this
  object. Each VIOLATION type's classification rests on the ABSENCE of any
  such route — no `TITLE_SHAPES` row (Algorithm/AlgorithmStep/List/Link/
  MathTail/Citation), or a row that gets a tiddler nothing ever transcludes
  (Theorem/Proof) or that no code path ever calls (CodeListing) — verified
  by reading `TITLE_SHAPES`, `_BLOCK_TYPES_IN_SECTION`, `BLOCK_TEMPLATE`
  and `_build_inventory`, not by counting.

  The percentage table above is CORROBORATION of that route-level
  classification, not the standard itself: every BY_DESIGN and every
  VIOLATION type happens to read EXACTLY 100.0% unreachable corpus-wide,
  and every OUT_OF_SCOPE type happens to read between 20.2% and 89.5% (a
  working path with real but partial gaps, per `conserve.py:189-311`'s
  five verified mechanisms — see FIX ROUND 1 below). That the two bands
  never overlap is a useful cross-check that no route was misjudged — a
  route that were actually only 60% effective would show up as a number in
  the gap between them — but a type is BY_DESIGN or a VIOLATION because a
  route was named and verified or because none could be, not because its
  number happened to land on 100.

CONCERNS
  The committed `conserve_baseline.json` covers seven documents, not the
  1,362-document corpus. That is a deliberate scope decision (stated
  above under WHAT WAS BUILT), not an oversight: the full corpus lives in
  a private, deny-by-default library that this repo's tests and CI cannot
  see, so a baseline entry for a document nobody running this repo can
  open would be untestable data. `pdfdrill conserve <pdf> --gate` on any
  OTHER real document gets zero tolerance (an empty baseline row) until
  someone adds one — which is the same posture `type_contract` already
  takes with an unclaimed corpus type, not a new one invented here.
  FIX ROUND 1 (findings 1, 2, 3, 7, 8, 9 of the review at
  task-656-review.md): OUT_OF_SCOPE's 13 types were re-verified
  individually against source, not left as one templated string. Five
  DISTINCT mechanisms, not one, each with its own line-cited proof
  (`conserve.py:189-311`): (A) block-level Section children — Paragraph,
  Equation, Table, Picture, Diagram, ListItem, Abstract, Sidenote, all
  transcluded by the ONE `_section_body` loop (`tiddlywiki.py:1698-1730`)
  gated on `_BLOCK_TYPES_IN_SECTION` (`:686-688`); (B) inline per-line
  substitution via `subs_by_line` — Formula and Reference, built by
  `_build_inline_subs` (`:860-950`) and applied at the SOLE
  `subs_by_line.get(anchor, [])` call site inside `_transclude_paragraph`
  (`:1558`, grepped for every use — there is exactly one); (C) footnote
  marker regex-match — Footnote alone, `_substitute_footnotes`
  (`:1614`) against `fn_by_refnum`, confirmed to never touch `subs_by_line`
  at all; (D) build-time baked marker — LtxCommand alone, its
  `{{title||LTX}}` written into the hosting text's OWN `props["text"]` at
  LaTeX-ingestion time (`pdfdrill.latex_source._capture_ltx`), before the
  model exists, never a `tiddlywiki.py` runtime substitution; (E) section
  listing, not transclusion — Section alone, listed by the root/TOC or a
  parent's "## Subsections" block (`:1736-1740`). Types sharing one literal
  code path share one literal explanation (the same convention
  `BY_DESIGN["TableRow"]` already used for `TableCell`); no type was left
  unverified and none needed to move into the ratchet — all thirteen's
  measured rate (20.2%-89.5%) is consistent with a working path, not a
  missing one, for its own now-cited reason.
  `1511.08771` (4.96 GB model) was excluded from the corpus measurement
  entirely — the population is 1,362 of the 1,363 models this library
  currently holds, not 1,363. Its own reachability is unmeasured by this
  task.
  The gate was verified against real documents by calling
  `docops.conserve.gate`/`conserve` directly (as `cmd_conserve` itself
  does internally) rather than by invoking the `pdfdrill conserve --gate`
  CLI entry point on penev_A / SteerableWaveletFramesBasedontheRieszTransform:
  the CLI path calls `_stale_or_absent` first, and running it against
  live, valuable library documents risked triggering an unwanted
  `cmd_model` rebuild pass. The review independently drove `pdfdrill.cli.
  main()` end to end on a synthetic on-disk model and confirmed FAIL/PASS
  give real shell exit codes 1/0. `_do_conserve`'s own flag-stripping
  (`--gate`/`--json`/`--limit`, `cli.py:1539-1550`) — verified by the
  review only by hand — now has its own automated test
  (`test_do_conserve_parses_gate_json_and_limit_flags`,
  `tests/test_cmd_conserve_gate.py`), stubbing `cmd_conserve` and asserting
  exactly what five different flag combinations pass it.
  The committed baseline's seven real-document rows still cannot be
  exercised by running the gate against the real documents that produced
  them (rule 19 — unchanged by this round). What CAN be and now is tested:
  every row names only a type `classify_unreachable` would actually ratchet
  (never a BY_DESIGN or OUT_OF_SCOPE type, which would make the row
  silently inert) with a positive integer count
  (`test_every_committed_baseline_row_names_only_ratchet_eligible_types`),
  and one real row, replayed as a synthetic document carrying exactly that
  many objects of that type, gates at exactly that baseline through the
  SAME `gate()` a real invocation uses
  (`test_a_committed_baseline_row_gates_a_document_at_that_exact_count`).
  That is more than parseability; it is not the same as running `conserve
  --gate` against 1811.06102 itself, which rule 19 still forbids in CI.
