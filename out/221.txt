WHAT THE FIX IS
------------------------------------------------------------------------------
Fallback FONT, not _MATH_CMD. There is no LaTeX command for 口 or ১, and
_MATH_CMD maps a character to a command (\pm, \alpha). U+53E3, U+5B5B, U+5B80
and U+5315 are all in Noto Sans CJK JP, already declared; U+09E7 needed a new
family, guarded:

   \IfFontExistsTF{Noto Sans Bengali}{\newfontfamily\fbbeng{...}}{...}

Guarded because an unguarded \newfontfamily for a font the machine lacks
ABORTS the compile and writes no PDF — strictly worse than the dropped glyph
it was added to prevent. Absent the font, the character drops as before and
glyphs_dropped() says so, which is a failure we can at least see.

AND THE ENUMERATION HAD TO GO. _FB_CJK listed 24 code points by hand. The four
in this task were not among them; U+5315 from out/219 was not either. Coverage
is now measured from the font FILES with fontTools and stored as ranges, the
same way _COVERED_RANGES already was — 12 ranges for CJK, 14 for Bengali.
COVERAGE, not blocks: a block test routes a character to a font that may not
have it, which turns a dropped glyph into a dropped glyph with an extra step.

THE FIRST FIX WAS WRONG AND THE REBUILD SAID SO
------------------------------------------------------------------------------
Mielke went 20 -> 9, not 20 -> 0. Two defects the four code points had been
hiding:

**(a) A fallback family is a TEXT font switch and does nothing inside $...$.**
`{{\fbcjk 」}}` fires, looks right in the source, and the glyph drops anyway,
because in math mode the character is still set by the math machinery, which
falls through to the main font. U+300D dropped exactly ONCE in Mielke — at its
single math-mode occurrence — while its three \ttfamily occurrences in the
Source column set correctly. Now:

   \newunicodechar{C}{\ifmmode\text{{\fbcjk C}}\else{\fbcjk C}\fi}

This is the lesson _MATH_CMD's own note records — "\setmonofont fixes the
\ttfamily Source column and does nothing inside $...$" — written about the
font branches and then not applied to them.

**(b) The \text{} escape lands in the font nobody measured.** The _COVERED
branch emits \ifmmode\text{C}\else C\fi on the strength of _COVERED, which is
DejaVu Sans MONO's coverage. \text{} selects the MAIN font, which is serif.
Serif lacks **917** of those code points. Mielke lost U+0644 (Arabic lam)
eight times this way, in math, after the CJK and Bengali families were already
in place.

Most of the 917 is not exotic: U+2244, U+2262, U+2300–237A, U+27E6/27E7 — the
mathematical operator blocks — are all mono-only here, which is to say all of
them were one math occurrence away from vanishing. Both halves of the
declaration now name the font that was actually measured. Characters serif
DOES carry are untouched: changing a glyph that was never in danger is the
out/097 regression (six 1205.3463v2 rows moved 1–2 units WORSE in the ink
compare).

**(c) And then the enumeration problem demonstrated itself, live.** With the
batch already running, Lie Groups came back 6 -> 1: U+2FF0. _FB_CJK lists five
of the twelve Ideographic Description Characters by hand (2FF1 2FF4 2FF8 2FFA
2FFB). Noto Sans CJK carries all twelve. One of the seven nobody had typed
dropped in the very rebuild that was fixing four other hand-listed code
points. The IDC block is now a range.

ONE CHARACTER NO INSTALLED FONT HAS
------------------------------------------------------------------------------
Seven Sketches ended at 1: U+27C28, CJK Extension B, PLANE 2. Checked against
the font file rather than assumed — Noto Sans CJK does not carry it, and
nothing else installed does. It goes to _NO_FONT and prints \textbf{[U+27C28]}.

That is the correct outcome, not a failed fallback. The row still differs from
the scan, but VISIBLY, so its residual is attributable and the other 4,292
rows stay measurable. Refusing the whole document over one hallucinated
Plane-2 ideograph would be the worse trade.

Seven Sketches then reached 0.

214 MUST NOT MEASURE A REPORT THAT DROPPED GLYPHS
------------------------------------------------------------------------------
report_tex.ink_measurable(log) -> (ok, reason). The residual compares RENDERED
ink against SCANNED ink; a glyph the engine discarded is absent from the render
and present in the scan, indistinguishable from a glyph the OCR never emitted.
The number comes out as an extraction defect when the defect is a missing font.

The exit code cannot carry this. xelatex wrote the PDF and returned 0, and the
PDF is perfectly good to READ — only measuring is unsound, and the only place
that distinction is recorded is the log. out/213: six of eleven reports were
in this state and every one of them exited 0.

cmd_reporttex now refuses, and THIS IS THE WRITER FOR report.ink.json.REFUSED
— a state reporttex has recognised since 180 and nothing has ever produced.
The measurement is not discarded, it is renamed, so the refusal is on disk and
reversible. Verified end to end on 0707.4470:

   residuals REFUSED: report.log reports 1 dropped character(s) — Missing
   character: There is no g ("67). A residual measured against this report
   would charge a font gap to the extraction. Quarantined as
   report.ink.json.REFUSED; rebuild this report, then re-measure.

and the page itself carries a third note, because a refusal is not an absence:
"no residual measurement has been run" would be false when one has been run
and refused, and "could not be paired" would blame the report's table for a
missing font.

THE SIXTH REPORT — AND THE ADVICE THAT WAS POINTING AT THE WRONG PLACE
------------------------------------------------------------------------------
0707.4470 drops one character and no font can fix it:

   Missing character: There is no g ("67) in font rsfs10!

"67 is TeX hex — 0x67, ASCII lowercase **g**. It is `\mathscr{g}`, and rsfs10
has no lowercase at all. out/219 predicted the old warning was wrong here; this
run confirmed it. The message said "add the code point to _MATH_CMD or a
fallback font", which is the one place the answer cannot be. It now reads:

   U+0067 is not a Unicode coverage problem: the character 'g' was set in
   rsfs10, a TeX math ALPHABET that does not contain it (rsfs10 and eufm10
   have no lowercase). No fallback font can reach it — change the command,
   not the font.

The repair is a script alphabet with lowercase (mathalpha scr=boondoxo,
dutchcal). NOT done here: those packages REPLACE \mathscr for all letters,
changing every uppercase \mathscr glyph in every report in the corpus, and the
ink residual depends on unchanged columns as a control (HANDOVER rule 16).
That is a change to make deliberately, with a rebuild, not as the tail of a
different task.

WHAT THE CORPUS LOOKS LIKE, MEASURED
------------------------------------------------------------------------------
1,101 reports have a log. **58 have dropped glyphs, 399 in total**, in four
classes:

    194  \text{} escape landing in serif, or a fallback used in math  <- fixed
    133  non-ASCII reaching a TeX math font with no _MATH_CMD entry
     49  mono genuinely lacks it (_NO_FONT territory)
     15  an ASCII letter in a TeX math alphabet (the 0707.4470 class)

The 133 is dominated by two characters: **Å (U+00C5) 56 times across 16
documents** and **ð (U+00F0) 65 times**, both in cmmi10. Both are below 0x100,
and unicode_decls's _COVERED branch is guarded `c > 0xFF` with the comment
"Latin-1 accented letters already set correctly in the maths fonts". 121 drops
say that is not true for these two.

NOT fixed here, for a stated reason: a plain _MATH_CMD entry emits
\ensuremath{...} unconditionally, which would also rewrite every Å in the
\ttfamily Source column where DejaVu Sans Mono renders it correctly today —
the out/097 regression again. It needs the mode-aware form, and a rebuild to
verify. Largest single remaining win, 16 documents.

Also not done: making the FALLTHROUGH default a visible marker, so a character
with no home can never vanish silently. Measured before rejecting: DejaVu
Serif carries **1,042** code points above 0xFF that mono does not, and they
render correctly today with no declaration at all. A blanket default would
replace 1,042 working characters with [U+XXXX] markers. It needs serif
coverage measured and stored first, exactly as mono's was.

A NEAR MISS: THE REBUILD DRILLED ITS OWN OUTPUT
------------------------------------------------------------------------------
The batch script picked its input with `ls "$dir"/*.pdf | head -1`. Once a
report has been built the directory contains report.pdf too, and collation put
it FIRST for exactly one of the six documents — "report" sorts before "Seven".
So Seven Sketches was rebuilt as a report OF its own report: 26 pages instead
of 679, 50 malformed rows, one compile error.

It did not clobber anything — the output went to a report.pdf.drill/ sidecar
and the real report.pdf was untouched at 679 pages — but it would have been
reported as this document's result had the page count not been absurd. Three
byproducts were removed (report.pdf.drill/, report.pdf.drill.json, a 9 MB
report.lines.json) and the document rebuilt properly.

The general shape: **the drill's own output became eligible as its input the
moment the drill succeeded**, and the selection rule had no way to tell a
source document from an artefact. A page count two orders of magnitude wrong
is what caught it; nothing in the pipeline would have.
