579 - REPORT BEFORE THE BUILD

WHAT STEP 2 CURRENTLY STASHES

  commands.py, cmd_inkreport, step 2:

      held  = doc / "report.ink.json"
      stash = doc / "report.ink.json.inkreport-hold"
      if held.is_file():
          held.replace(stash)

  It hides the whole ink file at the FILESYSTEM level for the duration of the
  measure build, and restores it in a `finally`. Nothing else is stashed.

  This is a blunt instrument for a narrow purpose: the only thing it is
  trying to prevent is the measure build STAMPING itself phase=reading.

THE FOUR FUNCTIONS THAT DECIDE

  1. ADOPTION - commands.py, cmd_reporttex
        ink_path = default_ink  if report.ink.json is present
        ink_map  = rt.load_ink(ink_path) if ink_path else None
     With the file stashed, ink_path is None and ink_map is None. This is the
     only consumer of the stash.

  2. ROW SELECTION - report_tex.findings_rows(tiddlers, bibkey, doc_dir,
                                              ink=..., refined=...)
        code = ink.get(title, {}).get("code", "")
        ... doubted  if conf < DOUBTED_MAX_CONF and code[:1] in INK_AGREES
        ... flagged  if code[:1] in INK_FLAGS
     `corrected` comes from corrected_pairs(doc_dir) and `unresolved` from
     renderable(latex) plus _contradicted_identifiers(doc_dir). Neither reads
     the ink. So with ink={} exactly two of the four sections can be
     populated, and two are empty BY CONSTRUCTION.

  3. BULLET EMISSION - report_tex.findings_tex, its inner row()
        bullet = "" ; if code: bullet = "~\inkbullet{...}{code}"
     `code` is passed only for the flagged and doubted sections
     (report_tex.py:2823). Corrected and unresolved rows call row() without
     it and never carry a bullet, in either phase.

  4. THE PHASE - report_tex.write_build_stamp
        "phase": ("measure" if (not legend and not ink_adopted) else "reading")
     where ink_adopted=bool(ink_map) is handed in by cmd_reporttex.

  So the phase is currently defined by WHETHER THE INK WAS READ, and the row
  set is a side effect of the same fact. That is the whole defect: one flag
  is carrying two meanings, and the measurement is taken against the shape
  produced by the wrong one.

WHAT A PHASE-1 BUILD WOULD CONTAIN IF THE INK WERE READABLE FOR ROW
SELECTION BUT NOT FOR BULLET EMISSION

  Identical to phase 2 in every respect that a measurement touches:

    - the same four sections, with the same captions and the same counts
    - the same \ident{} identifiers in the same table order, which is what
      inkconvert.identifiers() reads and what the TSV rows are paired against
    - the same report.tables.json manifest, which is what inkmeasure reads to
      segment the rasterised report into rows
    - the same page geometry, modulo the legend

  Differing only by:

    - no \inkbullet macro on any row (~1 macro plus a short code string per
      flagged/doubted row)
    - no legend footer

  That is what measured_against has been asserting all along: this ink was
  measured against THAT report. It can only be true if the two builds have
  the same rows.

THE CHANGE

  Separate "read the ink" from "show the ink".

    - findings_tex(..., bullets=True); row() emits a bullet only when
      `bullets and code`
    - build_report(..., bullets=True) threads it
    - cmd_reporttex(..., ink_bullets=True) threads it and hands it to the stamp
    - write_build_stamp(..., bullets=None) records "bullets" and computes
        phase = "measure" if (not legend and not bullets) else "reading"
      falling back to ink_adopted when `bullets` is not supplied, so every
      existing stamp and every existing caller keeps its meaning
    - cmd_inkreport step 2 stops stashing the file and builds with
      ink_bullets=False; step 5 and _bail build with bullets on

  `ink_adopted` then keeps its plain meaning - the ink was read - and is true
  in both phases. `phase` means what it says.

WHAT WAS BUILT

  report_tex.findings_tex(..., bullets=True)   row() emits \inkbullet only
                                               when `bullets and code`
  report_tex.build_report(..., bullets=True)   threads it
  commands.cmd_reporttex(..., ink_bullets=True)threads it, and hands it
                                               to the stamp
  report_tex.write_build_stamp(..., bullets=None)
        records "bullets" and computes
            phase = measure if (not legend and not bullets) else reading
        `bullets=None` falls back to ink_adopted, so every stamp written
        before 579 and every caller that does not pass it keeps its phase.
  commands.cmd_inkreport step 2  no longer stashes report.ink.json; builds
        with ink_bullets=False. The try/finally that existed only to
        restore the stash is gone. `_bail` still recovers a hold left by an
        interrupted pre-579 run, so an upgrade cannot strand one.

`ink_adopted` now means what it says — the ink was READ — and is true in
both phases. `phase` is decided by the legend and the bullets.
