THE ZERO IS A FINDING, NOT AN ABSENCE OF ONE
------------------------------------------------------------------------------
   'not set up for use with LaTeX' is inputenc's message, and inputenc is
   a pdfLaTeX facility. These reports compile with xelatex, where the
   input encoding is never in question and a character either exists in
   the font or does not. Zero occurrences across 1,702 compiles is direct
   evidence of the engine — and it is what makes \DeclareUnicodeCharacter
   the wrong instrument for 090.

CORRECTION - THIS FILE UNDERCOUNTS, AND 091 IS WHY IT WAS FOUND
------------------------------------------------------------------------------
   xelatex writes the warning in TWO forms and this scan matched one:

     Missing character: There is no X (U+21D2) in font [lmroman10-regular]
     Missing character: There is no X ("3C3) in font cmmi10!

   The first is a fontspec-loaded font, the second a traditional TFM font.
   Every cmmi10 loss — i.e. every character dropped inside $...$, which
   turned out to be the majority — was invisible to the regex above. The
   figures in this file are therefore a FLOOR. 1912.12689 reads 508 here
   and had 72 more that this pattern could not see.

   The guard built in 091 matches both forms, and a test asserts it, so
   the check cannot pass by being unable to see the failure.
