PER ENVIRONMENT - THE TWO SOURCES DISAGREE SYSTEMATICALLY
------------------------------------------------------------------------------
                  author e-print     MathPix tex.zip
    lstlisting           0                 9
    minted               0                 0
    verbatim             0                 2
    algorithm            8                 0

   MathPix never emits algorithm and the authors never emit lstlisting.
   All 8 documents whose author source opens the algorithm environment come
   back from MathPix as lstlisting — 8 of 8, no exceptions.

   An algorithm float is a structured object: numbered lines, keywords, a
   caption, a float position. lstlisting is a verbatim code block. The
   content survives the conversion and the structure does not.

   Consequence for anything comparing the two sides: an algorithm in the
   author source will NEVER match by environment name. A comparison keyed
   on the environment would report 100% disagreement on all 8 and would be
   measuring the mapping rather than the OCR.

CORRECTION 1 - "THE AUTHORS NEVER EMIT lstlisting" IS FALSE
------------------------------------------------------------------------------
   The per-environment table above reports 0 author lstlisting and I wrote
   that authors never emit it. That was true of 49 documents and is false of
   488: 41 authors open lstlisting and 4 open minted.

   The corpus is a mathematics-heavy sample. It contains almost no papers that
   typeset source code, so "0 of 49" measured the sample, not LaTeX practice.
   The wording above generalised from it and should not have.

CORRECTION 2 - THE MAPPING IS NOT 8 OF 8
------------------------------------------------------------------------------
   Above: all 8 author-algorithm documents come back as lstlisting, "8 of 8,
   no exceptions". At library scale there are 15 documents with an algorithm
   environment AND both sources:

       11  ->  lstlisting
        4  ->  verbatim        (1906.02691, 2510.11170v2, 2605.12061v1,
                                2607.05794)
        0  ->  algorithm

   So MathPix renders an algorithm float as EITHER a code block or a verbatim
   block. "8 of 8" was 8 documents all landing on the more common of two
   branches; the second branch existed and the sample had none of it.

WHAT SURVIVED THE WIDER POPULATION
------------------------------------------------------------------------------
   MathPix never emits the algorithm environment. 0 of 235 tex.zip documents,
   0 of 3,297 lines.json documents, against 97 authors who use it. That is the
   claim worth keeping, and it is now measured on a population 5x and 67x
   larger rather than on 49 documents.

   Also intact: 0 author-only rows among documents with both sources. MathPix
   marks code-like content wherever an author did; it disagrees about the
   NAME, never about the presence.

A NOTE ON THE lines.json DETECTOR
------------------------------------------------------------------------------
   18 hits over 3,297 documents, against 79 over 235 for tex.zip on the same
   kind of content. lines.json is much weaker: the verbatim wrapping happens
   when MathPix assembles a .tex, not in the per-line JSON. Its coverage is
   13x wider and its sensitivity is far lower, so its 18 is a floor and not an
   estimate. Do not read it as "18 documents in the library contain code".
