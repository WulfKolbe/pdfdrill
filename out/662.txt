TWO JUDGEMENT CALLS ON THE PROMOTED CODE
-------------------------------------------
1. THE ESCAPE BUG — FIXED. The original walker tested `s[j-1] != "\\"` to
   decide whether a `{`/`}` was escaped: correct for `\{` (one backslash),
   wrong for `\\{` (an escaped backslash, THEN a real unescaped brace) and
   for any even-length backslash run before a brace — looking one
   character back cannot tell those apart. Fixed in the style
   `has_bare_align_marker` (report_tex.py) already uses for the identical
   class of problem: a backslash is consumed together with whatever
   follows it, so a bare `{`/`}` is never re-examined on a later
   iteration and the walker never looks backward.
   Tested: tests/test_text_escapes.py::
   test_escaped_backslash_before_brace_is_not_an_escaped_brace — for
   `\text{a\\{b}}` the old walker (reproduced inline in the test, since the
   buggy code no longer exists to call) returns span end 11 (`s[6:11] =
   "a\\{b"`, missing the real closing brace); the fix returns 12
   (`s[6:12] = "a\\{b}"`, fully balanced). Also
   test_escaped_brace_is_not_counted pins the case the OLD code already
   got right (`\{`, one backslash), so the fix does not regress it.

2. \operatorname — EXCLUDED from the CJK gate's notion of "text mode",
   KEPT in the general list. `TEXT_IN_MATH` answers a FONT question for
   tools/audit_glyph_sites.py: which face renders a glyph inside a
   `$\displaystyle ...$` cell, and `\operatorname` really does set its
   argument in the main/roman font, same as `\text`. The CJK gate asks a
   different, CONTENT question: is this ideograph prose, or a
   hallucinated decomposition sitting inside some brace group? The
   auditor's own pinned case — `\mathrm{中}` stays REJECTED because "a
   math alphabet is not text mode" — applies just as much to
   `\operatorname`: it selects an upright math alphabet for an operator
   NAME, not a sentence, and CJK inside one is far more likely to be OCR
   misrouting a variable name than an author writing Chinese. So
   `CJK_TEXT_MACROS` (text_escapes.py) is a second, narrower regex used
   ONLY by cjk_defect, excluding `\operatorname` (and `\mathrm`, never in
   either list).
   FIX ROUND 1 (minor finding 4): `TEXT_IN_MATH` and `CJK_TEXT_MACROS` were
   two independently-spelled regexes differing only in `\operatorname`'s
   presence — coherent and tested, but able to drift if a third macro were
   ever added to only one of them. Both are now DERIVED from one list,
   `_FONT_MACROS`, minus `_CONTENT_EXCLUDED` (today: `{"operatorname"}`)
   for the narrower one — a macro added to `_FONT_MACROS` reaches both
   regexes automatically unless also named in `_CONTENT_EXCLUDED`.
   Tested: tests/test_cjk_text_scope.py::test_9_operatorname_cjk_is_refused;
   tests/test_text_escapes.py::
   test_operatorname_is_not_in_the_cjk_text_macro_list (contrasted directly
   against test_operatorname_is_in_the_default_font_audit_list, which pins
   TEXT_IN_MATH's unchanged behaviour) — both re-verified against the
   derived regexes, unchanged in observable behaviour.

THE COMBINED DECISION TABLE (report_tex.cjk_defect) — REVISED, FIX ROUND 1
----------------------------------------------------------------------------
The FIRST version of this table had text-scoping REPLACE the run-length
rule inside a text span (any run, however short, permitted unconditionally
once inside `\text{}`/`\mbox{}`/etc). An independent review, backed by
direct inspection of the three rows this actually changed on a real
document (BH1org_OCR — see POPULATION 2 below), found that "inside
`\text{}`" carries ZERO discriminating power for a run of exactly ONE on a
non-Chinese document: MathPix's own symbol-guessing produces the identical
shape (a lone wrong ideograph) whether or not its guess happens to land
inside a text macro, and BH1org_OCR's three occurrences are all run length
one and all read as that failure mode, not prose (one is a single-
character slot in a 3-row matrix column; two stack an EMPTY `\text{}`
against a one-character `\text{}` via `\stackrel`, a notation-decoration
shape no author types by hand). Corrected rule: TEXT-SCOPING RELAXES THE
RUN-LENGTH RULE INSIDE A TEXT SPAN, IT DOES NOT SWITCH IT OFF THERE — a run
of ONE still refuses in EITHER location; the bar that moves is the
THRESHOLD for what counts as "long enough to be text", not whether the
rule applies at all. `CJK_TEXT_RUN_MIN` (2) is that lowered, in-text-span
threshold; `CJK_RUN_MIN` (3) is the unchanged, bare-math threshold.

  | class \ location                          | inside CJK_TEXT_MACROS | outside (bare math) |
  |---------------------------------------------|-------------------------|----------------------|
  | IDC (U+2FF0-2FFB)                            | REFUSE                  | REFUSE               |
  | `\zh` command                                | REFUSE                  | REFUSE               |
  | run == 1 (a single stray character)          | REFUSE  <- fix round 1  | REFUSE               |
  |                                               |   added this row;       |                      |
  |                                               |   was PERMIT before     |                      |
  | CJK_TEXT_RUN_MIN <= run < CJK_RUN_MIN (== 2)  | PERMIT  <- the one cell | REFUSE               |
  |                                               |   662 actually relaxes  |                      |
  | run >= CJK_RUN_MIN (3)                       | PERMIT                  | PERMIT               |

Justification per cell (full version lives as the cjk_defect docstring,
report_tex.py, so it travels with the code):
  - IDC, either location: not a glyph, a RECIPE for one; only the
    decomposition path ever emits one, so location cannot change its
    meaning. Unscoped per the auditor's explicit instruction. Unchanged.
  - `\zh`, either location: existing pin (test_zh_command_is_flagged
    refuses `\zh{x}` where "x" isn't even CJK) and the docstring's own
    worked example show `\zh` as a decomposition companion marker, not a
    deliberate language switch. Unscoped for the same reason as the IDC
    row. Unchanged.
  - run == 1, EITHER location — FIX ROUND 1: REFUSE. Every "legitimate
    Chinese" example this gate's own history cites (判别式法, 符合题意,
    对零件i跳过检测, and the auditor's OmniDocBench population) is
    multi-character; none supports treating a lone character as prose
    merely for sitting inside braces, and BH1org_OCR's three real
    occurrences of exactly this shape are all hallucinations.
  - CJK_TEXT_RUN_MIN <= run < CJK_RUN_MIN, INSIDE a text span: PERMIT.
    THE cell that is genuinely relaxed: two consecutive ideographs inside
    `\text{...}` (e.g. `\text{的确}`, "indeed") get credit for being marked
    as text that the same length would not get bare in math — a bounded
    relaxation (one character's worth), not a bypass.
  - the same run length, OUTSIDE a text span: unchanged from 617 — no such
    credit without a text macro around it. REFUSE. This is also WHY
    `\mathrm{中}` and `\operatorname{中}` both still refuse: neither macro
    is in CJK_TEXT_MACROS (judgement call 2), so a single ideograph inside
    either one is "outside a text span" by this table AND additionally
    hits the run == 1 row.
  - run >= CJK_RUN_MIN, either location: unchanged from 617 (a run this
    long is text by construction, measured, in EITHER location — measured
    again here: BH1org_OCR's three hallucinated occurrences are all run
    length one, never two or three).

Rule 17's fixture: tests/test_cjk_text_scope.py, now 16 cases (12 -> 16,

REFUSE pair for the relaxed run==2 threshold, and added the two real

THE TWO MEASUREMENTS, KEPT APART (rule 12)
-----------------------------------------------
Method: report_tex.cjk_defect is measured under THREE configurations by
MONKEYPATCHING the two module globals it reads at call time
(`rt._CJK_BLOCKS`, and the `text_spans` name bound into report_tex's
namespace) — not by hand-copying the algorithm a second time, the same
method task 659 used for its own before/after:

  OLD          narrow _CJK_BLOCKS (pre-662), no text-scoping at all
               (structurally = task 617's gate)
  TEXT_SCOPED  narrow _CJK_BLOCKS (unchanged), WITH text-scoping
               (the FIXED, fix-round-1 algorithm — relax, not bypass)
  FINAL        widened _CJK_BLOCKS (662), WITH text-scoping
               (today's shipped report_tex.cjk_defect, unmodified)

  delta A (text-scoping alone)   = TEXT_SCOPED vs OLD,         range held narrow
  delta B (range-widening alone) = FINAL       vs TEXT_SCOPED, scoping held on

Re-run after the fix round 1 correction (all three configurations were
re-measured with the corrected `cjk_defect`; the monkeypatch harness itself
did not need to change, since it patches the same two globals the fixed
algorithm still reads).
