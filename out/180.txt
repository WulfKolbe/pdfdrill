THE ONE PLACE I DID NOT FOLLOW THE COPY EXACTLY, AND WHY
------------------------------------------------------------------------------
The sentence asserts a CAUSE: that the table could not be read reliably enough
to pair. That is true of 0902.0431 and of BradleyGastaldiTerilla2023. It is
FALSE of a document nobody has measured — nothing failed to pair there,
because nothing was attempted, and the note would be telling a reader that a
measurement was tried and defeated when none was ever run.

That is the defect class this whole sequence has been about: an artefact
stating a reason it cannot verify. So there are two sentences, and the report
chooses between them from what is on disk rather than assuming:

   report.ink.json.MISPAIRED / .REFUSED present   -> the note above, verbatim
   no ink file of any kind                        -> "no residual measurement
                                                      has been run for it"

Both end identically — "MathPix confidence is shown; the residual column is
absent" — because that half is what the reader HAS, and it is true either way.

Checked against both real states:
   0902.0431                    report.ink.json.MISPAIRED  -> unpairable note
   BradleyGastaldiTerilla2023   report.ink.json.REFUSED    -> unpairable note
   1206.0238                    no ink file                -> not-run note

NO INTERNAL VOCABULARY ON THE PAGE
------------------------------------------------------------------------------
A test asserts the note contains none of: lattice, coverage, inkdrill,
enclosure, 0.015. A reader does not need to know what a lattice is to
understand that a column is missing and why it would matter.
