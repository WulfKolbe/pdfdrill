404 / 405 / 408 — `pdfdrill inkreport`
=======================================

ONE COMMAND, and the only supported way to produce an ink-updated report.

  preflight -> build --no-legend (phase=measure) -> measure -> inkconvert
  --force -> build with legend+ink (phase=reading) -> publishready

`--no-legend` is INTERNAL now. It was accepted by the CLI, absent from the
manifest, `--help` and SKILL.md, and forgetting it stamped the build
phase=reading so the measurement taken against it was refused five steps
later (400). A flag that must always be passed at one step and never at
another is not a flag.

`inkconvert` is called with --force. It refuses to overwrite, which in 396
made me compare a file against ITSELF and report 100% agreement — the only
answer that test could have given.

TWO DEFECTS FOUND BY RUNNING IT
-------------------------------

Both were found by the command's first real run, and both are the false
alarm a check exists to raise, raised by the check itself.

1. THE BIBKEY WAS THE DIRECTORY NAME. `publish_ready` called
   `rt.ink_join(tiddlers, d.name, ...)` and `rt.rows_for(tids, d.name)`.
   Under the self-contained layout the folder IS the bibkey, so it worked and
   kept working. Under the legacy layout the folder is `<name>.pdf.drill`,
   which matches no identifier — so on this document the residual check
   reported

     "NONE of 99 measured identifiers matches a row here — a join failure"

   and the index check reported "cannot read equations", on a document whose
   99 identifiers matched perfectly. Fixed with `_bibkey_of`, which reads the
   model. Both call sites use it.

2. PREFLIGHT ACCEPTED ANOTHER DOCUMENT'S EVIDENCE. The first version globbed
   `*.lines.json` in the PDF's folder. ~/Downloads holds dozens, and it
   passed on `Visual_analysis_of_documents_with_semantic_graphs.lines.json`.
   A check that accepts someone else's evidence reports a readiness nobody
   has. Now named for the document's own stem. `report-crops/` is shared in a
   flat folder too, so crops are counted by the document's own bibkey prefix.

ONE HONEST NOTE ON THE PROBE. A 20 s network timeout per document is not a
corpus sweep, so `preflight` takes `probe` and `probe_timeout`. With the
probe off the scan column is reported as UNKNOWN, not as fine: a sweep that
assumed 200 would report a corpus ready that nobody checked.
