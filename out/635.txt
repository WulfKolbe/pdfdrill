MEASURE FIRST — THE MODEL, BEFORE ANY EDIT
--------------------------------------------------------------------------
`doc.objects_of_type("Toc")`: exactly ONE Toc object on penev_A
(`obj_8607767a6fae`), `derived: True`, `derived_from: "section_header"`
(`docmodel.modules.toc.TocProcessor`). Its props carry `entries` (162
leader-stripped titles) and `rows` (241 title/locator/raw triples) — one
FLAT list. Its `surface` realization spans anchor indices 71..361 of
`mathpix_lines` (291 lines, pages 2-3) — the first/last `table_of_contents_*`
-typed line in the document, because `TocProcessor.find_items` walks ONLY
those four types (container/row/item/number) and ignores `section_header`.

THE BEFORE-YOU-BEGIN CHECK, RUN AND ANSWERED. Does the Toc's own realization
cover the three wreckage Section objects' own lines?
  Section "Contents"        (line 69, index 69) — NOT in [71, 361]
  Section "List of Figures" (line 70, index 70) — NOT in [71, 361]
  Section "List of Tables"  (line 354)          — IS in [71, 361]
2 of 3 header lines sit OUTSIDE the Toc's own claimed range — measured, not
assumed. Read out of the actual mathpix_lines payloads (`out/635/script.py`'s
model section, plus the ad-hoc dumps this task ran first): "Contents" and
"List of Figures" are two adjacent `section_header` lines immediately BEFORE
the first `table_of_contents_container` line; `TocProcessor` starts its span
one line later than either heading, by construction. This is EXACTLY the
"before you begin" trap the brief named, and it does not block the task: the
brief's own step 2 already gives two INDEPENDENT, evidence-based rules —
drop the three Sections BY NAME (no Toc coverage needed to justify it: a
`\tableofcontents` supersedes a hand-written "Contents" section regardless
of where its header line sits) and drop every OTHER object anchored on the
Toc's own claimed lines (evidence off the Toc's own anchors). Checked
against the actual wreckage: every one of the 23 orphan Formula objects and
both orphan Sidenotes sit strictly inside [71, 361] — the Toc's realization
covers 100% of the actual orphan content, even though it does not cover 2 of
the 3 header anchors themselves. NEEDS_CONTEXT was not warranted; reported
here instead, in full, per rule 12 (an unexplained delta is a finding).

LIST OF FIGURES / LIST OF TABLES — ARE THEY SEPARATELY REPRESENTED?
NO. `entries[0..94]` are the chapter/section Contents; `entries[95..157]`
are List of Figures captions; `entries[158..161]` are List of Tables +
Appendix table entries — all in the SAME flat `entries`/`rows` list, no
sub-region boundary prop. There is no model evidence to emit
`\listoffigures` / `\listoftables` from, so they are NOT emitted — their
entries stay dropped-and-counted under `toc_region_suppressed` exactly like
every other TOC-line fragment, per the brief's own fallback instruction.

WHAT WAS BUILT
--------------------------------------------------------------------------
  src/docops/projectors/latex.py
    `_render`'s "Toc" branch (previously absent — a Toc in flow rendered
    "", out/646's finding): emits `\tableofcontents` ONCE, at the Toc
    object's own flow position (`flow_ordered_content` already places it
    there; no new flow-index arithmetic needed).
    `_prepare` gains the 635 suppression block: (a) every Section titled
    Contents / List of Figures / List of Tables, BY NAME; (b) every OTHER
    object (any type, any realization role="surface", ANY anchor of the
    realization — NOT limited to a 634/646-style "block claim") that
    touches an anchor the Toc's own realization spans. (b) is deliberately
    NOT 634/646's block/inline claim rule — that rule answers an INPUT-side
    question (does counting this as a second consumption make a nested
    formula look like lost/mixed content?); 635 answers an OUTPUT-side
    question (does this object print standalone in the flow?), and
    penev_A's 23 orphan Formulas carry ONLY inline (sub-anchor offset/
    length) realizations on their TOC lines — no Paragraph claims a TOC
    line to transclude them FROM — so the block-only rule (first
    implementation, this task) caught 0 of them. Re-measured against the
    ACTUAL rebuilt .tex (rule 14: re-measure against the current artifact)
    and broadened to any-realization-touches, which is safe because: every
    object that touches the Toc's span at all has its EARLIEST realization
    (the one `document_flow.DocumentFlowProcessor` uses for `flow_index`)
    also inside the span — checked exhaustively on penev_A, 0
    counterexamples — so a suppressed object never had a legitimate
    rendering anywhere else; it prints exactly once, and that once was the
    TOC. `CONTAINER_TYPES` (634/646's own `("Page",)` exclusion) is reused,
    not reinvented, and excluded from the count for the same reason 634/646
    exclude it: a Page is not even a flow content type
    (`common.CONTENT_TYPES`), so it was never going to render standalone,
    and counting it would report an action that never happens.
    Counts land in `self._toc_region_suppressed: dict[type, int]`.
  src/docops/projectors/beamer.py
    `_render` grows a "Toc" branch returning "" — beamer already hard-codes
    its own Outline frame's `\tableofcontents`; without this override the
    shared `_render`'s new "Toc" branch would print a SECOND one wherever
    the Toc object's flow position lands a beamer content frame.
  src/pdfdrill/commands.py
    `cmd_latex`'s report gains one line: `toc_region_suppressed: <n> <Type>,
    ...  (in the projection; the model keeps them)` — printed only when
    non-empty (a count nothing prints is a count nobody reads, 638's rule,
    reused).
  tests/test_latex_projector.py
    12 new tests (TDD; the first 6 confirmed failing for the right reason
    before any implementation existed, then 3 more once the block-only
    first cut under-suppressed against the real corpus): a Toc emits
    `\tableofcontents` once; the wreckage Contents section is dropped from
    the projection but NOT from the model; a block-claimed TOC-line Formula
    is not emitted standalone; real content after the TOC region is
    untouched; `toc_region_suppressed` counts the Section and the Formula;
    a Formula OUTSIDE the Toc's range is not suppressed (evidence, not
    position); an INLINE TOC-line Formula (penev_A's real shape) is ALSO
    suppressed; a `Page` container touching the Toc's span is never
    counted; no Toc → no `\tableofcontents` and nothing suppressed (a
    Section literally titled "Contents" is left exactly as the model
    states it when there is no Toc to justify replacing it).

this task (Section detection quality, not TOC handling) that was simply
INVISIBLE before because no `\tableofcontents` existed to surface it. Not
fixed here; named so it is not mistaken for a 635 regression.
