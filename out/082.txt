SHAPE
------------------------------------------------------------------------------
   title       <bibkey>_LST<nnnn>, matching the _EQ/_FO/_TAB family so the
               existing index and report tooling finds them by one pattern
   text        the listing body, VERBATIM
   type        text/plain
   tags        listing <bibkey>
   fields      language, caption, label, bibkey, source_file, source_line,
               lines, kind=CodeListing, external_path when present

   type/text-plain is not cosmetic. TiddlyWiki renders text/markdown by
   running the markdown parser: four-space indents become code blocks
   inside code blocks, underscores become emphasis, backticks nest. A
   listing stored as markdown is no longer the listing.

   The projection deliberately does NOT go through TiddlyWikiProjector._t,
   which applies _to_markdown and stamps text/markdown. Reusing it would
   have been the obvious economy and would have silently rewritten every
   body. A test pins this with a body containing underscores, backticks and
   indentation.
