THE LITERAL CHECK CANNOT BE THE CHECK, AND SAYING SO IS PART OF THE ANSWER
---------------------------------------------------------------------------
`measured_against.sha256 == sha256(report.pdf)` is 0 of 21, and it would be
0 of 21 on a perfectly healthy corpus. 237b wrote down why: under the
two-phase build, phase 1 is legend-off and phase 2 legend-on, so the
measured file and the published file are DIFFERENT FILES BY CONSTRUCTION.
A check that refuses everything always is not a check.

So the gate asks the question that one was reaching for — is the measured
build and the published build the same report? — and it answers no, for a
reason far larger than a legend.

WHAT WAS BUILT
--------------
`report_tex.ink_describes_published(doc_dir)` -> (ok, detail). The chain is
checked link by link and every link names its own reason:

  1. measured_against present at all
  2. == sha256(report.pdf)                -> ok, "measured this exact file"
  3. else == the surviving measure stamp  -> or it describes neither
  4. report.pdf == its own reading stamp  -> or the file is not what it says
  5. same formula_rule, same model_sha256
  6. same `findings` shape
  7. same page count                      -> "a different set of rows, not
                                             a legend"

Wired into `publish_ready` as its own check named `stamp`, and added to
PUBLISH_CHECKS so it prints. It is deliberately NOT folded into `ink`: that
check asks whether a measurement exists and covers the rows, this one asks
whether it was made against this build, and the second was never asked.

`build_stamp` now records `findings`. The shape was the cause and the page
count only the symptom; a stamp that cannot say which shape it is cannot
distinguish a legend from a rebuild. On the 21 existing stamps the field is
absent on both sides and compares equal, so today the page count is what
catches them — the test covers both paths.

TESTS
-----
2,926 passing, three new: an ink naming no build, a measurement of a
different shape (and, with the shapes forced equal, of a different page
count), and an ink that measured the exact published file.

Two existing fixtures had to state their own preconditions rather than
inherit them. `_doc` now writes a measured_against by default, because a
fixture whose ink named no build was asserting readiness for exactly the
state this gate exists to refuse; and `test_build_stamp._stamped`, which is
about an ink with no provenance, now asks for that explicitly.

WHAT THIS DOES NOT DO
---------------------
It does not re-measure anything. All 21 published documents are now NOT
READY by a check they were always failing silently, and the fix is a
re-measurement against the findings build — `inkreport` phase 1 on the
current shape — not a loosening of the gate.
