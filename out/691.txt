======================================================================
(B) johnston EQ0439 and "the figure frame in math"
======================================================================
The user named johnston-linear-matrix-algebra_EQ043. EQ0043 itself is fine
(ink N|+0, rendered). EQ0439 is the figure-frame row, with EQ0114 and EQ0575
the same class in the same book; all three print "(not rendered)" in
evidence-equation.pdf and have no ink row.

THE CAUSE IS OURS, IN THE MODEL BUILD, NOT MATHPIX'S
  lines.json, p170, the math line under a figure parent:
    text          '\[ \begin{aligned} {[A \mid I] } & = … \]'        CLEAN
    text_display  '\begin{figure} \[ … \] \captionsetup{…} \caption{…}
                   \end{figure}'                                     FLOAT
  src/docmodel/modules/equation.py:212
    latex_raw = payload.get("text_display") or payload.get("text") or ""
  reads text_display first, so the whole float — caption included — becomes
  the equation's latex.

CORPUS, measured over 1,367 lines.json
  math lines with \begin{figure} in text_display   42 in 21 documents
  of those, `text` is clean                         42 of 42
  of the clean `text`, renderable() accepts         41 of 42
    (the one refusal: Schaum's p308, an array — a separate cause)
  Currently rendered: 0 of 42.
  Published documents affected (site reports/ slugs): johnston 3, lyche 4,
  kohlhase-omdoc 1 — 8 rows in 3 documents. The other 34 rows are in 18
  unpublished documents.

WHERE "THE CHANGES" WENT — they were never on this path
  446 (09-01)  leading-opener rule in report_tex.renderable — declines here
               by design: the \end{figure} is present, so the opener is
               "balanced".
  483/485      _drop_leading_furniture (report_tex.py:1388) — strips a
               caption BEFORE the \[, not after the \].
  446's own text classified these 42 as "whole floats with captions —
               434's work" and stopped.
  434 (08-31)  the reclassification design — "Design report only; nothing
               implemented."
  657 (09-10)  inventoried 446/483/485 as present, which is true: present
               and reader-side only, in the PDF report's gate. Nothing in
               src/docmodel ever detected the frame (git log -S shows no
               docmodel change since 2026-05-31).
  446 was also wrong on one point: it said the value "genuinely IS a
  figure". MathPix's `text` for the line is the equation alone; the float is
  only in text_display.

PROPOSED FIX — not built
  equation.py: for a math line, take `text` when text_display wraps a float
  (or prefer `text` for math lines outright — needs a corpus diff first,
  because text_display may carry other intended differences).
  Cost: a model rebuild renumbers FO identifiers, which invalidates every
  crop and ink row keyed on them (667, HANDOVER), so each of the 3 published
  documents needs rebuild + re-measure + publish (johnston, lyche,
  kohlhase-omdoc). The 18 unpublished ones need only the rebuild.
  Alternative with no rebuild: the same `text`-over-float rule reader-side in
  report_tex.renderable — a sixth reader, which is the pattern 674 regretted.
