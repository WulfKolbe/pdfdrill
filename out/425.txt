428 — WHY THE SECTION READS `latex`
-----------------------------------

`report_tex.rows_for`, one line, applied to all four kinds at once:

  report_tex.py:105    latex = t.get("latex") or t.get("latex_code") or ""

`latex` is set on Equation and Formula. It is set on ZERO Table objects,
corpus-wide — not "usually unset", not "set to something else": never set.
So the tables branch of that line can only ever produce "", and the cell
falls through to the apology.

AND THE LOSS HAPPENS ONE STEP EARLIER THAN THAT

`rows_for` reads TIDDLERS, not model objects. The TAB tiddler's fields are:

  created, height, modified, page, tags, text, title,
  top_left_x, top_left_y, type, width

No `latex`. No `mathpix_text`. 0 of 42 on chung2019combinatorics. The
tabular is dropped by the TiddlyWiki projection, so by the time `rows_for`
runs there is nothing to read under any name. Fixing `rows_for` alone would
change nothing.

DID 290's PROPS INVENTORY CATCH IT? YES. IT IS IN THERE, CORRECTLY.

  | prop | objects | on types | written by | read by |
  | `latex`        | 643,364 | Equation, Formula | … | comparison_html.py,
                                distill_reader.py, formula_report.py +15 |
  | `mathpix_text` |  11,119 | Table             | pdfdrill model |
                                docmodel/modules/table.py, pdfdrill/commands.py |

Both facts that would have prevented this are on those two lines:

  * `latex` is on **Equation, Formula** — Table is not listed. A reader
    asking "can I read `latex` for a Table" had the answer.
  * `mathpix_text` is on **Table**, and its READERS are `table.py` (which
    writes it) and `commands.py`. Neither the TiddlyWiki projector nor
    `report_tex` appears — the inventory recorded that nothing in the
    projection path reads it.

The only reader outside table.py is `commands.py:9907`, a `_norm()`
comparison, not a projection.

So the inventory did its job and nobody consulted it. That is the failure
CLAUDE.md names in the other direction — "a capability exists, is written
down, and gets rebuilt anyway, because nothing in the path forces a look" —
and here it cost 10,928 rows an apology instead of their content.

WHAT WOULD HAVE TO CHANGE (not changed here; 425 is a measurement)

  1. the TiddlyWiki projector carries `mathpix_text` onto the TAB tiddler
  2. `rows_for` reads it for the tables branch, as `latex` for that kind
  3. 423's column then has something to put in it, on 99.1% of published
     table rows

The 14.1% with neither are the honest remainder: a scanned table MathPix
gave no tabular for. Those keep an empty cell, and 426 decides what an empty
cell says now that it will no longer point at tables.html.
